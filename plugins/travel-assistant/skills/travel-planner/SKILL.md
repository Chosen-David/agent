# 旅游规划

读取 [完整工作流](references/workflow.md)，按其中的输入补全、能力发现、证据、时间可行性和交付标准执行。

先复用最新行程和会话。识别已订事项、用户想做的活动和未知项，一次只问1–3个关键问题。酒店未订先比较区域；一日游用集合点，不强加住宿。指定项目不能无声删除。

动态发现并阅读当前环境真实可用的天气、地图、联网查询、documents/docx、pdf或表格Skill。最低能力不足时明确降级，不把工具名、脚本下载、插件分发配置当作已经安装或已授权的服务。

在仓库环境读取 [backend registry](../../../../config/backend_registry.json)。如果 JourneyPilot 已由用户实际部署并配置好所需 provider，可优先复用它的持久旅行 workspace、provider/MCP research、证据绑定 itinerary、map/report/PDF、resume 与 bounded edit；其结果仍按本 workflow 验收。JourneyPilot 不可用时直接用当前平台能力，不要求为了单次旅行部署整套服务。

按目的地当地日期核查天气、节假日营业窗口、最后入场/点单、预约与精确分店。为交通、排队、运动恢复、休息和返程留量；区分核验事实、历史参考、估计、未知和冲突。超出预报范围只给气候参考，公共园区全天开放不代表馆舍全天营业。

美团/小红书/点评/携程等只通过实际可用且获授权的接口或平台允许的公开查询/浏览器处理。无接入就给来源或请用户提供必要截图，不编实时余量，不绕过登录、验证码或访问控制，不自动联系商户、下单或取消。

经验贴只辅助判断动线、拍照和排队风险，记录原帖日期与实际读取范围，不用旧帖代替当日营业事实。覆盖午间的旅行日默认留60–90分钟独立午休，用户可调整或取消；怕累时优先保留。核实午休用房与交通；先缩减可选活动，不以吃饭、排队或乘车替代休息。

逐段比较当地经济且方便的通勤：给准确起终点/入口、方式、线路与方向/换乘、包含步行候车的全程时间、费用单位和一句推荐理由。人数分摊、体力、行李、天气一起考虑；没查到的路线或报价明确标估计，推荐方式变更同步重排。

新增条件更新同一行程版本，重算关联时间与路线。按用户要求生成真正的Word等文件，通过对应Skill完成渲染检查与持久化后交付；无工具则说明未完成的格式或验证。私人旅行资料不进入公共仓库。不自动启用后台天气监控。
