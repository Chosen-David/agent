# 执行与验收

## 执行要点

1. **先只读后写**：映射阶段不产生任何变更；CODEMAP/README 落盘前先展示表格让调用方可审。
2. **增量优先**：已有 CODEMAP.md 时只追加/修订本轮新条目，不重排历史行（diff 可读）。
3. **证据可查**：CODEMAP 每行至少一个可核对锚点（脚本路径、结果文件路径或 commit）。
4. **提案落盘**：重组建议写 `docs/reorg_proposal_<date>.md` 或用户指定位置，含待拍板项列表。
5. **执行留痕**：授权后每次移动一个 commit，message 写「组织：X→Y，动机，回滚=git revert <hash>」。

## 验收清单

- [ ] CODEMAP 覆盖当前活跃脚本 ≥95%（活跃=最近一轮任务链产出或被引用）；
- [ ] 每个必要目录有 README 且 ≤10 行；
- [ ] 孤儿/重复清单有 grep 证据（引用计数）；
- [ ] 无运行中管线路径被移动（检查后台任务日志/接力脚本）；
- [ ] 删除项 0 个被执行（全部在提案里等用户）；
- [ ] 移动项引用修复后目标脚本干跑通过。

## 失败降级

- 目录过大无法全量枚举时：只映射最近 N 天 mtime 的文件 + 其余标记 backlog；
- 无法确定某脚本归属时：CODEMAP 标 `unknown` 而不是猜；
- 用户仓库无 git 时：所有移动降级为提案（不执行）。
