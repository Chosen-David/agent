# 代码组织流程

## 何时运行

- 任务链每轮收官（监督器触发或用户显式要求"整理代码"）；
- 大实验轮次落袋后（新脚本/新结果超过 ~10 个文件）；
- 用户抱怨"不知道哪个对应哪个"时优先做映射而不是先动结构。

## 步骤

### 1. 建立映射（先读后写）
- 枚举脚本目录（如 `exp/trace/analyze_*.py`、`plot_*.py`）与结果目录（`results/*.json|md`）；
- 从脚本头部注释、输出路径字符串（`open(...)`/`json.dump` 目标）、git log 提取：实验代号 → 脚本 → 数据源 → 结果文件；
- 交叉核对：无脚本产出的 JSON（外部收割）与无结果落盘的脚本（半途废弃）都单独标注；
- 生成或增量更新 **CODEMAP.md** 表格：`| 代号 | 一句话结论 | 脚本 | 数据 | 结果 JSON | 论文引用 |`。

### 2. 目录 README
- 只给"必要目录"写：一级目录与承担明确职责的二级目录（scripts/results/figures/benchmark/docs）；
- 一段话功能说明 + 命名约定（如 `analyze_eNN_*` 按实验代号、`plot_*` 产图）+ 指向 CODEMAP 的链接；
- 不为琐碎目录制造空 README。

### 3. 重组提案（PROPOSE，不先动手）
- 孤儿清单：无引用、无结果、超期未用的脚本（grep 全仓引用 + 结果目录名确认）；
- 重复实现：同功能多版本并存 → 指出保留哪个（以最新 git 提交与结果完整性为准）；
- 命名漂移：同一概念多个名字；
- 每项标注：建议动作（归档/合并/重命名/删除）、风险、回滚方式（git mv 保留历史）；
- **删除永远留给用户拍板**；移动须确认无运行中管线引用（查 nohup/接力脚本/tmp 脚本里的路径）。

### 4. 执行（经授权）
- git 仓库内：`git mv` 保留历史，一次一个逻辑组，commit message 写明动机；
- 非 git 目录：先 `cp -r` 快照到 archive/ 再动；
- 移动后 grep 旧路径引用并同步修复，跑一次最小验证（相关脚本的 --help 或干跑）。

## 禁止

- 移动运行中任务的输出路径（接力脚本会写不进去）；
- 改动用户私人记录文件（如论文设计文档——用户明示不可修改的）；
- 把整理当成重写：不趁组织之机重构代码逻辑。
