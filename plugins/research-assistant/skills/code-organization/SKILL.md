# 代码组织

读取 [组织流程](references/workflow.md) 与 [执行与验收](references/execution.md)。适用于科研/工程仓库在迭代后积累大量按时间线命名脚本的场景（如 exp/trace 下 analyze_eNN_*.py 与 results JSON 的对应关系）。

核心交付三件：
1. **CODEMAP.md**（仓库或目录级）：实验代号 → 脚本 → 数据集 → 结果 JSON → 论文/报告引用位置 的表格，随任务链增量更新；
2. **目录 README**：必要文件夹（scripts/results/figures/benchmark 等）一段话解释功能与命名约定；
3. **重组提案**：孤儿文件、重复实现、命名漂移的清单与建议动作（合并/归档/删除），标注风险与回滚方式。

边界：不动运行中的管线输出路径；被论文或下游脚本引用的文件移动前必须 grep 全部引用点；删除永远留给用户拍板。可独立调用，也可挂入任务链监督器在每轮结束时自动执行文档部分。
