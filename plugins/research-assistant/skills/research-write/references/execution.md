# 执行与验收补充

这些步骤细化已有职责；不改变用户目标、权限或外部 API。按本次任务需要应用，不要求简单问答生成全套文件。

1. 写作前把核心主张映射到 evidence_id、来源位置、版本、指标定义和适用范围。元数据/DOI存在只能验证身份，不能验证引用支持；对关键句打开原文定位，缺引文标缺口。

2. 先组织证据与论点，再写连续正文，最后反查摘要、正文、图注的数字和强度。局部微基准不写成端到端，非显著不写成等效，post hoc 不写成预注册。负结果和失败配置不得选择性删除。

3. 模板、研究证据和输出 PDF 各自锁版本。生成文件、编译、内容核验、视觉审读分别记状态；只请求某段草稿时无需启动整篇投稿管线。未知作者、基金、伦理或实验信息留空并明确，不补似真的声明。

复杂交接附实际输入版本、产物路径、已执行检查、限制与下一负责人。外部后端发现不等于可运行或已授权；没有后端时用当前工具完成有界任务。

知识需求与交接按 [知识接入契约](knowledge_access_workflow.md) 执行；保留实际查询/前提核对证据及完整 knowledge_refs，无需求时注明原因。
