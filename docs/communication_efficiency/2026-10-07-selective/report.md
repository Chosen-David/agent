## 实际生产者、入口与消费者

生产者原始manifest → 原事件/产物/知识/记忆校验 → 消费者可信request → Mailbox.prepare_context → 原文依据payload → 独立核对/动作 → ACK。新字段只来自消费者；已消费request绑定不可改，改任务须新事件/run。

- `context_claim_ids` 指定本次结论，递归保留声明的祖先。required_claim_ids、必需知识/记忆、所有candidate/rejected声明及各自依据始终保留；`context_artifact_ids`可要求额外产物。知识与记忆前置闭包不截断，保留内容不做语义摘要。
- 未选正文依旧先核查，不用选择绕开过期依据；产物只传路径/hash，阅读大产物的后续工具成本另计。supported是结构声明，不能证明科学前提成立。
- 原有缓存提示只限此消费者当前上下文实际保有的完整正文；换上下文或压缩丢失内容须清空。引用、前提和原数据继续保留，更正仍重新检查。
- `make_token_counter`及CLI `--encoding / --max-tokens`使用可选tiktoken；消费者 `context_tokenizer`绑定编码。缺工具、编码不匹配或硬预算不足均停止派发，不偷偷截断。
- 主调度两入口、科研插件入口、通信工作流及15角色知识入口同步更新；没有新增Skill或检索服务。仅插件分发缺runtime时仍须按工作流明确手动契约边界。
