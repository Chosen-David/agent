# Bounded followthrough: fail closed on semantic acceptance

Authorization: follow through the identified three paper declaration false accepts and consumer-version gap; no paper drafts or SGLang changes. Base `b4fc439`. Original per-case failures and original host evidence remain immutable historical records.

Frozen success conditions before running the new controls:

1. Matching trusted consumer version and intact output passes; mismatched version rejects; missing consumer version is unverified in completion mode. Producer inline expected-version claims grant nothing. Integrity-only inspection remains explicitly distinct.
2. A completed paper without controller-supplied independent semantic acceptance is unverified, regardless of worker's self-declared pass or manuscript wording.
3. Trusted acceptance binds canonical full record, actual snapshot hashes, independent reviewer identity, concrete evidence, and pass decisions for artifact fit/originality. Changed record/content, same writer/reviewer, missing/rejected review, inline forged review cannot certify completion.
4. Actual completed role bindings parse start and completion receipts; dispatch/queued, wrong actor/role/revision, missing output/start events reject. Receipt structure/hash alone does not authenticate a host event.
5. Positive controls have genuine generated artifact bytes and explicit **synthetic test** trusted-controller evidence; they never count as model execution. Holdouts include alternate IDs/content, stale review, changed artifact, and unsupported receipt kinds.
6. Fresh blinded host roles exercise the committed current CLI/API and read actual artifacts. Independent reviewer verifies actual outputs. No worker receives fixed rubric or historical answers.
7. Full regressions, offline references and independent review before safe non-force main update. Keep normal-task QA active and development eval opt-in.

This gate does not automatically decide research quality or detect all plagiarism. A trusted caller must actually dispatch independent review and supply its acceptance out of worker control. Hash binding detects changes; it is not a signature or proof that a reviewer is honest. If the host cannot establish that trust boundary, acceptance remains unverified.
