## One small implementation change proposed, not implemented

One cohesive edit to `scripts/agent_eval_pipeline.py`, plus focused cases in its existing test module: add a **trusted, hash-bound material authorization** consumed by `prepare_run` before a run becomes dispatch-authorized. Keep numerical derivation in task-specific executable contracts; do not add a prose parser or a second runner.

Minimal interface: explicit `material_review` controller argument/CLI file, outside worker snapshot, with schema_version, reviewer_actor, planned_worker_actors, exact tasks/rubric hashes and per-case task/input hashes, complete criterion identity coverage, per-criterion kind (`factual` or `procedural`), verdict (`supported`, `contradicted`, `unreviewed`) and concrete evidence reference/hash. Criterion identity must include its exact text or canonical text hash and index/case; generic “all checked” entries insufficient. A procedural criterion may be supported as a valid task requirement without inventing a numeric oracle. A factual entry must identify a task-specific oracle result or located independent source check **and explicitly review the rubric-to-fact correspondence**. The independent reviewer owns that semantic correspondence; the pipeline does not pretend to infer it.

Fail closed for dispatch authorization unless every criterion is covered exactly once, all are supported, evidence bindings match, and reviewer is distinct from each planned worker. Missing/malformed/duplicate/tampered/stale/contradicted/unreviewed authorization must fail. Bind authorization hash and planned actors in manifest; existing record_start checks must require a matching authorized actor and review binding. A different worker requires reauthorization. Preserve ability to prepare an explicitly `unreviewed` research snapshot for diagnosis, but **such a snapshot must not be dispatchable**. An explicit reviewed preparation path rejects both known contradictory contracts; legacy preparation cannot be reported as a passed coherence gate.

Host order must be review→authorized preparation→host spawn→record_start. record_start observes an already-started event, so a check added only there would be too late to satisfy “before dispatch”. The repository does not control arbitrary host spawning; root/controller must call authorized preparation before it invokes the host. Record this trust boundary rather than claim OS enforcement. No rubric answers or review evidence enter task inputs/snapshot. Independent grader retains controller-only access.

This proposal is a record/dispatch boundary, not a universal factual verifier. A dishonest or mistaken trusted reviewer can still approve wrong content, just as existing semantic_acceptance relies on actual independent review. To close CO-020, the following measured correspondence controls are mandatory; shape tests alone cannot suffice.
