# 记忆更新与纠错：四篇原始论文阅读记录

阅读日期：2026-10-06。固定版本，非“最新排行榜”。已核对已有论文登记，以下四篇不重复此前阅读。阅读了正文方法与实验，并针对迁移问题阅读附录；逐节范围、作者、版本、未读范围见 `memory-papers.json`。以下论文数值均为作者报告，本库尚未复现，也不代表当前 Codex/Claude 的性能。

## M1 — LongMemEval

[Wu 等，arXiv:2410.10813v2，2025-03-04](https://arxiv.org/html/2410.10813v2)。§§3–5 将记忆评价拆成提取、跨会话、时序、知识更新及拒答，区别检索与最终回答。Table 3 中，round 索引增加 fact 后，GPT-4o top-10 QA 为 0.670→0.720；不是所有摘要压缩都有效。§5.2 显示只存摘要/事实会丢细节；§E.5 有正确召回却答错的情况。§E.4 的弱模型错误时间过滤会删除正确候选。商业产品实验发生于 2024-08，不用于判断现有产品。

**本库候选与最小实验（工程推导）**：保留源会话，摘要只作索引；冻结一组纠错、历史查询、未知问题，分别测来源召回、当前答案正确率、旧结论泄漏率和拒答率。不得用训练/调参题替代冻结集。核心验收是修正后旧答案不能重新作为当前证据出现。

## M2 — A-Mem

[Xu 等，arXiv:2502.12110v1，2025-02-17](https://arxiv.org/html/2502.12110v1)。§3 原子笔记同时存原内容、时间、生成标签/上下文和链接；新笔记可更新邻居描述。Table 1 的 GPT-4o-mini 多跳 F1 为 A-Mem 45.85、MemGPT 25.52；GPT-4o open-domain 却是 48.43 对 60.16，不能说全面更优。Table 2 给链接与演化消融。§B.4 按任务类别/模型调 k，GPT 常取 40/50；不应当成固定 k=10 的公平全任务结果。§6 承认组织质量依赖底模。

**本库候选与最小实验（工程推导）**：自动重组限定为可重建的检索索引，不能覆盖原始记录、用户要求或验收结论。将标签/关系版本化；在固定同 token 预算下比较无链接、人工依赖链接、生成链接，保留退化类别。语义相似链接只供召回，不能自动当成因果依赖。

## M3 — MemGPT

[Packer 等，arXiv:2310.08560v2，2024-02-12](https://arxiv.org/html/2310.08560v2)。§2 区分当前上下文和外部存储，通过函数分页检索；逐出上下文后仍保留 recall 记录。Table 2 的 GPT-4 Turbo DMR 93.4% 对基线 35.3%，但基线读有损递归摘要（§3.1.1），不是完整历史。§3.2 文档问答仅抽样 50 题；模型会过早停止检索，函数能力影响结果。附录评审允许宽松匹配，不能直接作为科研结论判据。

**本库候选与最小实验（工程推导）**：每次接手只装载当前任务、有效结论、关键纠错与证据入口，长日志按需读取。预算限制检索次数/字节；上下文淘汰不删除源证据。冻结恢复情境测试跨会话能否找到原始配置和正确需求版本，另测资料不足时明确未知。

## M4 — Zep

[Rasmussen 等，arXiv:2501.13956v1，2025-01-20](https://arxiv.org/html/2501.13956v1)。§2.1 区分原始 episode 与派生事实并关联来源；§2.2.3 记录事实有效时间与登记/失效时间，矛盾使旧边失效。Table 2 的 GPT-4o LongMemEval 是 60.2%→71.2%，即 11.0 个百分点；Table 3 的 assistant 信息类别退化 94.6%→80.4%。这是作者服务实验，非独立复现。§2.1 明言来源连接未在实验中直接评测；时序更新也未验证科研产物的传递失效。

**本库候选与最小实验（工程推导）**：借鉴来源+时间+历史保留；另外实现显式依赖闭包与报告发布门禁。构造“误解目标→配置→测量→结论→报告”链，纠错后阻止依赖的当前用途，保持原始字节和无关分支不变；重新核验后新版本才能进入当前报告。

## 针对本项目的纠错设计建议

以下是结合用户需求提出的工程设计，不是论文已验证的本库收益，也不是对云端产品隐含记忆的控制能力声明。

1. **明确纠错对象。** 保存用户更正的来源、接收时间、旧需求版本、新需求版本、原因和影响范围。用户现在改变目标，与用户指出“你过去一直理解错了”不同：前者是目标在某时刻变化，后者是旧解释从来未成立。不能都写成“旧结论直到今天仍正确”。
2. **分开真实性与适用性。** 假设旧意图是测均值，用户其实要 p95。旧日志如果确由该配置采集，其字节及“这次测到了什么”仍是历史观测；“满足 p95 任务”这个结论无效。若留有逐样本数据，可新计算 p95；若只有均值，必须补采，不能从均值虚构 p95。
3. **记录有方向的依赖。** `claim/report/decision → intent/data/code/config`；依赖必须是实际消费关系。纠正意图时把旧解释标为 superseded，并把依赖它的计划、结论、工作流记忆和报告标为需要复核。原始文件保留；本轮任务资格也可撤销，但不改写测量历史。
4. **阻止重新污染。** 当前检索和最终验收默认排除失效/待复核节点；历史查询可以返回，但必须携带显著状态、纠错原因和替代节点。摘要、索引和最近报告都重建，已经拿到旧快照的 agent 在提交结果时再次核对版本。
5. **原子变更。** 新更正、旧节点状态、依赖闭包与审计事件作为一次事务写入。主 AI 串行确认需求修订；其他 agent 提交证据和受影响列表。中断重试须幂等，不产生第二次纠错或“复活”旧节点。
6. **恢复要求。** 新任务/结论引用新需求版本并通过独立核验；不能靠改状态字段让旧结果变成新证据。仅某条依赖得到更正不意味着同节点其他失效依赖已解决。保留 rollback 到历史视图的能力，不将 rollback 等同于恢复当前有效性。

最小测试应覆盖多层依赖、共享依赖、无关分支、重复纠错、晚到旧结果、历史查询、缺源证据和部分补跑。LongMemEval Appendix A.4 的知识更新评分允许同时提旧信息，只要新答案满足问题；本项目的验收还须单独禁止把旧结论作为当前有效证据，不能直接套用这一宽松判分。随后才做有模型的配对评测；确定性回归通过只能证明这些状态转换被执行，不能宣称科研推理准确率提高。
