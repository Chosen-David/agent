# 实际消费者前提核对

消费者仍为model-with-knowledge → KnowledgeStore/SQLite → show/context → knowledge_refs。新增的是可调用的知识，不是生产检验器。当前主AI入口与角色注册表已路由到该Skill，保持不变。

审计输入：当前main的docs/agent_eval_pipeline.md、evals/tasks.json与evals/knowledge/queries.json。固定目录、合成任务、开发后修订和反馈重试用于工程验收；管线冻结模型/工具/预算和逐案例评分，明确“一次成功不建立成功率改善”。该目录没有声明IID总体抽样协议，也没有每次新样本的条件均值证据。

|理论条件|仓库实际证据|结论|
|---|---|---|
|分数范围[0,1]或已知归一化范围|个别通过/失败分数可归一化；多准则评分不是天然同一概率目标|需逐任务定义|
|零假设下每次新样本条件均值固定|公开固定案例目录和反馈返修，不是已证明的总体抽样|未知/不可认证|
|参数只由过去信息决定|当前没有新序贯检验器；反馈后选最好结果会泄漏|不得假设已满足|
|模型/工具/预算对照|管线有固定配置字段，但本轮没有两模型运行|仅支持协议审查|
|误报预算和停止规则事先固定|本轮数值实验已固定；实际生产无此检验协议|实验限定|

迁移拒用：不得把当前角色通过计数当作独立随机样本，自动颁发总体提升或触发推送许可。本轮数值收益不能补足这些事实。单次用户任务的必做验收照常执行；统计总体证据不替代必做任务完整性。

跨域正例是已知范围传感器的条件均值检验；保留仿射归一化和量纲，代码校验财富相同。调度完成、论文真实性或GPU速度为不同对象，不能套用证据财富。本文是主AI人工前提核对，无独立模型拒用测试声明。
