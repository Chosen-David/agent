# Opt-in lossless basis tables

A consumer supporting ordinary JSON plus both v1 table formats can request `"context_format":"auto-lossless/v1"`. It must supply an actual `token_counter` (or `--encoding o200k_base` in the communication context CLI). After the existing source/closure checks, the host enumerates complete decodable packets, filters both character and token caps, and minimizes `(tokens, characters, format order)`, with JSON first on an exact tie. The wire remains ordinary JSON or one of the two existing table versions; there is no new abbreviated value schema. Unknown table fields fall back to complete JSON rather than disappearing. If no complete candidate fits, the call fails. Consumer request immutability still applies. This avoids forcing column headers on tiny packets; it does not establish provider/session token cost or reader quality.

Consumers that also support memory tables can explicitly request `"context_format":"basis-tables/v1"` through the same entry points. This retains the claim table below and represents `memory_entries` as `{ "columns": [...], "rows": [...] }`. The exact memory column order is `id`, `kind`, `content`, `source`, `scope`, `evidence`, `status`, `created_at`, `document_refs`, `deps`. Each row contains all ten original values, including full prose, provenance, correction state and dependencies. No dictionary, external cache or persistent already-read state is required. The default and `claims-table/v1` remain compatible.

`decode_basis_payload` restores either version to ordinary JSON objects. New memory fields require a new supported schema: the encoder refuses missing/extra fields instead of dropping them. The new encoder also refuses packets exceeding the strict decoder's 200,000-character or nesting boundaries. Source/dependency checks run before encoding; character and actual-token budgets apply to the complete encoded payload, including version and columns. Changing format on an already consumed delivery remains forbidden. A table is a transport representation, never a validity or acceptance certificate.

Only use this format with a compatible consumer. If a host expands tables before sending text to the model, the expanded model input is the relevant cost. Small packets may grow; local payload-token measurements do not establish total model usage or reader quality. The current scoped accounting and negative controls are in [memory-pack-20261021](../../agent_doc/results/memory-pack-20261021/).

The existing consumer request can contain `"context_format":"claims-table/v1"` when calling `Mailbox.prepare_context` or the `communication prepare-context` CLI. The default remains ordinary JSON. All existing delivery, source, freshness, dependency and budget checks run first. A table saves repeated field names; it neither deletes negative evidence nor summarizes prose. Small handoffs can grow, so this is explicitly selected by a compatible consumer, not a global default.

The payload's `evidence_claims` contains `columns` in this exact order: `id`, `status`, `depends_on`, `artifact_ids`, `knowledge_ids`, `memory_ids`, `assumptions`. Each row is the corresponding full JSON values, with no scalar abbreviations. Consumers must map columns to rows and retain status/assumption/dependency semantics. `agent_runtime.handoff_encoding.decode_basis_payload` reconstructs ordinary JSON values. This decoder does not validate scientific truth, freshness or authorization; pass reconstructed source data through the existing relevant gates. Unknown versions, columns, fields and incomplete rows fail instead of being truncated. Knowledge/memory text and artifact reference hashes remain unchanged.

Research boundary: [Routed Graph Handoff, arXiv 2608.25277v1](https://arxiv.org/html/2608.25277v1), methods §2 and experiments/limitations §§3–4, reports that a graph-only handoff can regress on adaptive tasks and requires receiver interpretation guidance. This supports testing an explicit format with its consumer, not assuming all structured representations improve quality. Our key-interning transport is not its typed graph or LLM router; its benchmark gains are not this repository's measurements.

Keep the existing immutable consumption binding: a consumer cannot switch format on a previously consumed delivery. Use a distinct consumer or a new event/run. Host budget arguments may become stricter without changing the bound request.
