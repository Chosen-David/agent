# GPU 实验多机派单工作流

[返回](../README.md) · [技能入口](../plugins/research-assistant/skills/gpu-experiment-dispatch/SKILL.md)

## 职责与触发

`gpu-experiment-dispatch` 承担多机 GPU 池的实验派单组织：把臂×任务×档位×
期望行数的实验矩阵规划成确定性分片，派发到 SSH 远程 + 本地混合 GPU 池，
负责点火验证、定时监督、收割落袋。主 AI 是唯一协调者：确定实验口径、
授权起跑、批准判决措辞；本角色不改变统计门禁、不修改实验代码、不新建
远程凭据。

- 主 AI：给定实验矩阵与口径判定（哪些臂重跑、哪些复用）、授权起跑、
  审批判决与措辞。
- 派单 Agent：盘点、规划、脚本、点火、监督、收割；交付分片表、验证
  留痕、对账结果与证据 manifest。
- 实验 Agent：维护被跑的实验代码与打分实现；派单 Agent 消费其接口，
  不替它改行为。
- 审查 Agent：复核证据链可复验性（manifest 绑定、协议显式化、措辞纪律）。

## 阶段流

### 阶段 1：接入盘点（只读）

SSH 封装以机内既有文件为准；逐机过四清单（GPU 空闲、模型路径、数据集
覆盖、基准数据 root）+ python/磁盘。代码同步用 `rsync -a --delete` 且
`--exclude` 保护远端既有实验数据；同步后 compileall + 关键 import 冒烟，
三机全绿才进阶段 2。任何一项盘点失败即回报主 AI，不硬闯。

### 阶段 2：规划

产出三件交付物供主 AI 审阅后执行：

1. **任务清点矩阵**：臂×任务×档位×期望行数（逐任务精确行数，同时作
   完成度门禁与 SKIP 阈值）；
2. **复用判定表**：口径相关臂全量重跑（新目录新 postfix，不与旧口径
   混池）；口径无关臂复用旧数据只补缺口；边界情形宁可重跑并注明理由；
3. **确定性分片表**：每任务一机一卡；长路径档位独占大机、重任务独占
   链头、链总时长估算与最长链标注。

### 阶段 3：派单与点火

lib + 机器脚本两层；`bash -n` 语法检查；远程 nohup + `</dev/null`
点火；30 秒内三重确认（ps 进程数 + `nvidia-smi` 显存 + log tail），
留痕进任务文档。任何一重不符：定位、修复、重派（SKIP 幂等使重派
零成本），不静默吞掉。

### 阶段 4：监督收割

2h 巡检：GPU 空闲 = 完成或异常信号，两者都触发动作——完成则 rsync
拉回 + best-file 对账 + 官方 scorer；异常则按 log 修复重派；空卡按
分片表包抄最重未跑任务。收官判定：best-file 口径逐格达期望行数，
不满足不判收官。

### 阶段 5：判决落袋

判决类结果绑可复验证据链：`input_manifest`（逐文件 basename/行数/
sha256）、显式 bootstrap 协议（RNG/B/seed/任务顺序/CI 取法）、脚本
入库；小数据（<10M）原始数据整库入库。措辞纪律：CI 含 0 写「未证明
优于 / 未检出差异」，等价主张须 TOST + 事前界值。microbench 与 e2e
双口径都测都报。

## 与任务文档的衔接

派单起跑、点火验证留痕、收割对账、判决落袋全部记入项目
`agent_doc/task/task_details/<ID>.md` 的 Progress 段；分片表与复用
判定表作为 Plan 附件固化，后续批次（断点续跑/补格）直接引用不重推导。
监督器退出条件：全格对账通过 + 判决入库 + 远端目录已拉回。
