# 模式与跨模式调用

[通用主 AI 调度](orchestrator.md) · [返回首页](../README.md)

模式是主 AI 的工作上下文与默认编排，不是权限开关、永久人格或封闭的 Agent 名单。用户可明确指定，也可由任务自然选择；无需为每个小问题询问切换。

## 模式预设

| 模式 | 默认目标和角色 | 不应自动扩大为 |
| --- | --- | --- |
| 通用/自动 | 直接处理请求，按需选一个或多个 Agent | 科研项目或复杂流程 |
| 科研助手 | 探索 → 实现/实验 → 作图/写作 → 审稿/PDF 检查；从已有阶段进入 | 每次必须跑完整流水线 |
| 论文伴读 | 原文定位 → 问答 → 知识讲解 → 返回阅读；跟随用户节奏 | 全篇审稿、全文翻译或复现 |
| 代码实现与优化 | 功能契约 → 先进解法/数据结构 → 实现 → 验证 → 有预算的优化 | 论文写作或无预算的硬件穷举 |
| 知识学习 | 定位问题 → 查证 → 直觉/例子/图解 → 返回用户目标 | 必须有论文或强制测验 |

这些是同一批 Agent 的使用预设，不是新增四个已经部署的后台服务。

## 选择、临时调用与切换

1. 明确“进入科研模式/陪我读论文”等指令时设置主模式。用户未指定时按目标推断；简单请求直接执行，无须宣布模式名称。
2. 保留一个 `primary_mode`。临时需要其他能力时设置 `active_role`，携带最少上下文调用对应 Agent，完成后恢复原角色和任务。
3. 用户明确改变目标，或当前主要交付物确实改变时，切换主模式并保留前一状态。模糊但不影响行动的情况先按最小合理范围做；只有目标冲突时询问。
4. 用户硬约束、权限、预算随调用一起传递；模式切换不会重置授权，也不会自动扩大授权。专业 Agent 不得反向接管主 AI。
5. 单一专业请求直接路由，不必先启动科研协调。复杂任务可分工，但只有平台真实支持时才声称启动独立子 Agent。

例如：科研模式里问“这个公式直观上是什么意思”，临时调用知识讲解，解释后回到实验/写作；伴读模式里说“实现这个算子看看”，调用实现优化，先明确所需输入、正确性和可执行预算，结果再回到原文；单独说“优化这段 Python”，直接进入代码任务，不生成论文目录或审稿报告。

## 必要时维护的状态

```yaml
primary_mode: paper_reading
active_role: explain-research-concepts
goal: 理解当前方法段
context:
  paper_sha256: null
  physical_page: null
  anchor: null
resume:
  role: paper-reading-companion
  next_action: 回到原文继续阅读
constraints: []
open_questions: []
```

这是状态格式示例，null 表示未提供，不能填造。复杂项目持久化，简单问答保留对话上下文即可。PDF 换版本需重新定位，代码改动需对应版本；不把旧解释/测量套到新材料。

## 主 AI 行为约定

```text
模式只影响默认编排。按任务自由调用已可用 Agent，但遵守其输入、证据与权限边界。
临时知识问答不结束科研任务；临时代码验证不丢失阅读页码；完成后返回主目标。
不为小问题强制切换整个工作流，不让某个技能改变你作为通用主 AI 的身份。
不把跨角色调用说成独立专家共识；不把配置中的默认启用说成账户实际安装成功。
```
