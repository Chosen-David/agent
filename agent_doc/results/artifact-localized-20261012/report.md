# 局部文本差分：只在真实变化区运行匹配器

基线 `71496c7b1f42b94616343683c7671b6a0e6e8a3b`，2026-10-12。实际入口为 `scripts/artifact_context.py` → `compare_artifacts` → `_edits`。

问题机制：现有实现即使只有中间一行变化，也会把最多 2,048 行完整文本送入 `SequenceMatcher(autojunk=False)`。共同首尾只可能形成 equal 区段，不参与 edit 输出，却仍进入潜在二次复杂度的匹配。候选在现有字符/行数上界之后，以线性扫描剥离逐行相等的首尾，仅匹配中段，再把 opcode 起点加回完整 base 偏移。双方文件仍先读取并做 SHA 校验；完整 base、候选选择、预算、恢复和 stale 拒绝不变；未引入缓存或第二份生产实现。

生产测量：`measurement.json` 固定 seed `8675309`，2,008 组空/Unicode/CRLF/插入/删除/重复/随机输入，在普通字节选择和完整 packet 字节计数两种模式共执行 4,016 次完整入口对照；全部能精确恢复，候选最终 JSON 比基线更大的次数为 0，164 个 packet 因更规范的局部 opcode 发生变化。2,048 行重复文本中间单行变化，7 对交替计时中位数 `619.523861 ms → 1.868739 ms`，降低 `99.6984%`。计时包含读取、SHA、候选选择和序列化；个别候选样本有调度抖动，但不改变宽裕阈值。输入与源码哈希、全部样本、Python/OS 见原始 JSON。

测试：21 项 artifact 定向回归通过。全库 1,172 项中 1,162 通过、8 跳过、2 失败；两项均为本轮前 main 已提交的知识 canonical/generated 副本不同步，且这些文件未被本任务修改。本轮不修 unrelated 基线问题，也不声称全库绿。

适用范围：收益只对已测合成局部编辑的 CPU `compare_artifacts` 入口成立，不外推模型质量、token、账单、GPU、网络或整个 Agent 请求。`ART-EQUAL-01` 只覆盖完全相同文本，本轮不重复其收益。近期已全文阅读的 *Agent Skills Can Be Harmful* 启发按额外步骤定位开销；本实现是经典共同首尾裁剪，不声称复现论文算法或新增论文精读计数。项目已有 T6/T15/COH-T20 的 10+ 篇全文阅读证据仍按原范围保留。

独立复核结论为 **FAIL，不可消费**：独立 6,032 次完整入口检查虽全部精确恢复，但发现 16 次最终 wire 增大；重复行使完整与裁边后的 `SequenceMatcher` 选择不同合法对齐。该候选已撤回且不会提交。完整反例与验收意见见 `independent_raw.json`、`independent_review.md`；后续修复不得覆盖这份负结果。
