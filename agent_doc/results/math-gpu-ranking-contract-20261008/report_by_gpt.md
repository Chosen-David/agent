# GPU 分数目标与证书迁移：Indexer 数学设计候选

Task-ID: MATH-51；日期：2026-10-08；版本1；状态：**待真实 kernel 验证的设计**。知识来源为本库 math.floating-dot-enclosure@1、math.residual-interval-screening@1、math.topk-margin@1；本文不改已有知识结论，不添加 Skill，不修改 SGLang。

## 先确定到底保留谁的排序

同一 query 下定义三个不同对象：量化/旋转近似之前的理想分数 t_i；存储的实际 post-RoPE q/k 按精确实数解释的点积 s_i；固定 dense kernel 的实际输出 g_i。mask、有效长度、缩放、bias、dtype、位置和 tie-break 都必须固定。若论文目标是相对 full attention 的候选质量，应明确 full attention 使用的分数对象；不能一边证明 s 的Top-k，一边把 g 的一致性当作结论。

再定义候选重算 kernel 输出 c_i。即使读取相同 q/k，候选列表改变矩阵形状/布局，仍可能改变 kernel、split-K、归约顺序；因此 c_i=g_i 是要核验的条件，而不是“完整维度重算”自动带来的事实。不同层、near/far分组以及prefill/decode也可能分别改变该条件。

## 经典基础与正式算术边界

IEEE 标量运算的正确舍入保证针对给定运算、格式与舍入模式；加法不具结合性，FMA仅舍入一次。NVIDIA正式文档的部分 f16/bf16/tf32 MMA说明不指定累加顺序、舍入和次正规处理；不把这个描述扩张为所有指令均未指定。dtype=FP32或重复运行相等，都不足以证明理想实数误差界。FTZ与量化必须另计。

来源：NVIDIA《Floating Point and IEEE 754》当前13.4文档§2.2、§2.3、§4.4；PTX ISA 9.4中mma的Precision and rounding以及相应scalar .ftz说明，2026-10-08访问。只采用正式算术语义，不将旧白皮书历史设备例子误认为当前设备测量。

## 本项目推导：将证书输送到明确的目标

假定已有逐token的真正外包 L_i≤s_i≤U_i，且有**经独立认证**的非负逐项界 |g_i−s_i|≤δ_i。直接由三角不等式：

\[
L_i-\delta_i\le g_i\le U_i+\delta_i.
\]

以这些膨胀后下界的第k大值为τ，只删掉膨胀后上界严格小于τ的token。证明：至少k个真实g值不小于τ；任意删项严格低于这些值，不能进入任何Top-k解。端点相等必须保留，未知δ、溢出、NaN或无合法外包都必须保留/回退，不能拿失败当小分数。

在候选内取g的Top-k即可恢复一个全局g的Top-k解；如需固定tie-break标签，重排同时采用原稳定token ID规则。若只能算c而不是g，则还需认证 |c_i−g_i|≤η_i，并证明候选内选择集合A满足每个i∈A、j∈C\A都有 c_i−η_i>c_j+η_j。该充分条件不成立只表示未知：做原目标精算或保留更宽集合，不能宣称排序错误必然发生。全量dense分数可能只为开发评估生成；不建议在线先算全量g再声称稀疏加速。

若目标是t且 |t_i−s_i|≤ζ_i，则使用区间[L_i−ζ_i,U_i+ζ_i]；ζ涉及量化、旋转实现、缩放/bias等实际差异，而非δ的别名。只认证s时不必平白加量化前误差；目标是g时不能以理想RoPE误差替代实际kernel偏差。

更细的实数账本：代理h满足 |h_i−s_i|≤ρ_i；实际代理计算\hat h满足 |\hat h_i−h_i|≤a_i，则 |\hat h_i−g_i|≤ρ_i+a_i+δ_i。三个界各自有适用对象，端点/范数/平方根/误差和的计算也必须向外舍入。ρ是逐项残差证书，不是平均重建误差、采样最大值或校准分位数；γ_n误差模型需实际运算图及范围前提，不能套给任意MMA。

这些是不带概率假设的条件式推导，不是本项目首创定理；无已认证δ时，GPU迁移状态仍为candidate。

## 可手工复核的正例、边界与拒用

以下均是公开设计例，**不是本轮运行数据或未见测试**。

* 正例：L=(9.8,8.8,0), U=(10.2,9.2,0), δ=(0.1,0.1,0.1), k=1。膨胀下界首项9.7，另外两项上界9.3和0.1，故只保留首项，所有符合区间的g均相同冠军。
* 边界：两项膨胀区间在τ处相交，不允许删除上界=τ者。k=N时保留全部；宽界可令C=N，安全性不保证收益。
* 换目标反例：s=(10,9.95)，δ=(0.1,0.1)允许g=(9.9,10.05)。s的冠军不再是g的冠军；“实数Top-k恢复”不能认证dense数值Top-k。
* 顺序反例：binary32 round-to-nearest-even，M=2^24。((M+1)−M)=0，而M+(1−M)=1，精确实数和为1。另一个token分数0.5便使冠军随运算顺序改变；相同输入/FP32不足以保证重算等于dense。
* FMA反例：a=1+2^-23、b=−(1+2^-22)，精确a²+b=2^-46。binary32非融合乘加为0，融合为2^-46，都是明确不同的运算图，不可共用“实际输出”定义。
* FTZ拒用：binary32最小正次正规x=2^-149，若输入或结果被flush，x·1变0，误差x大于u·x（u=2^-24）。单纯相对模型不覆盖该例；一邻接端点也不能对任意FTZ运算盲目认证。

**adapt**：在开发侧建立固定操作顺序的参考路径与逐节点比对，保存编译参数及运算图；**defer**：替换生产dense kernel，因为会改变性能基线且缺GPU数据；**reject**：把重复运行bitwise相同当作对精确实数的准确性证明。可复现、准确、排序稳定、稀疏质量是四种不同性质。
