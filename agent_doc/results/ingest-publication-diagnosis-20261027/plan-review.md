## Source-based assessment of the four frozen probes

1. **Ordinary success:** The fixture copies the independent version-1 Cauchy-Schwarz pair and creates a distinct candidate with that entry as its sole prerequisite. The original metadata has no prerequisites or relations, so the two-record staged graph is self-contained. Receipt/reference equality against a freshly loaded live corpus is a useful normal-path control. Copying verification metadata does not certify the synthetic draft scientifically; no such claim is proposed.

2. **Dependency removal during final copy:** Production first validates the combined private corpus, rejects an already existing target, and compares the current live snapshot with the initial snapshot. Only afterward does it copy the prepared candidate into the destination-filesystem private staging directory and rename it into canonical entries. The hook calls the genuine copytree first, then removes both prerequisite files precisely when source basename is `math.publication-probe` and destination basename is `entry`. The earlier whole-entries copy does not match that predicate. This therefore exercises a late window after live snapshot revalidation and before publication. KnowledgeStore checks that every declared prerequisite target exists for candidates as well as published entries; status affects additional version/published checks, not target existence. A successful return, visible imported directory, executed hook, and fresh live-store missing-target error would support the narrow finding that this interleaving accepts an entry with invalid declared dependency closure. The deletion is deliberately injected; it is not attributed to ingest itself. Removal leaves no original records, so a refusal before publication could instead yield an empty-corpus error; that alone would not establish acceptance of an invalid closure. The recorded refusal/existence/error fields permit these cases to be distinguished.

3. **Empty concurrent target:** The wrapper around the real os.rename creates the destination immediately before that exact rename, after ingest's prior target-existence check and final guard. It records the created directory's device/inode identity. Replacement by the distinct ready directory changes identity and installs the candidate files. That is a concrete ownership-preservation counterexample if observed on this Linux/POSIX filesystem. The POSIX skip condition is broader than Linux; reporting must name the actual recorded platform rather than claim all POSIX systems were measured. The hook models one specific interleaving and requires no live concurrent thread to establish that schedule's outcome.

4. **Nonempty concurrent target control:** The same hook adds owner.txt and records identity before real rename. Refusal, unchanged identity, and intact owner bytes provide the relevant collision control. The test does not require the whole corpus to become invalid for a nonempty unrelated directory; only the target owner's preservation is at issue.

The existing scope regression mutates the corpus after the initial entries snapshot copy and before the final snapshot check, so it covers an earlier rejected change and does not close the final-copy window. Existing import tests cover bad dependencies known before validation and duplicate IDs known before publication. They do not establish late dependency or last-instant empty-target preservation. The documents no-replace primitive is not a general portable ingest replacement; no repair is approved here.
