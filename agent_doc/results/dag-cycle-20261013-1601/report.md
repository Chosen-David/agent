# 稀疏深链 DAG 判环优化

公开 `core.validate` 入口的独立合成 CPU 计时：512节点链12.667863→1.604065ms，降低87.34%；1000节点链45.855008→3.242512ms，降低92.93%。只支持本机这些校验工作负载，不代表Agent任务质量、模型token成本或Store端到端收益。

## 实现与边界

Store.create的实际校验入口原来每轮扫描全部剩余节点；深链有V轮，容易形成二次重复扫描。先执行两轮原扫描，浅图无需额外邻接表；第三轮仅当剩余节点>=64、原依赖集合元素总数<=4×剩余节点、剩余与已访问节点/依赖全部exact builtin str且依赖在剩余或已访问集合内，才对残余图用Kahn拓扑判环。先从依赖集合扣除已访问节点，构建入度/反向邻接，再逐边释放。小图、密集图和特殊hash/eq字符串保留原扫描。

这是经典图算法的本库工程应用，不宣称论文算法创新。准入阈值限定稀疏深图，避免密集图邻接构造开销。命中路线期望O(V+E)时间和O(V+E)辅助空间，前两轮仍计时；未命中路线保留旧复杂度。对全validator不声称线性，因为字段、成员和JSON检查还有自身开销。保持原图构造、字段/异常顺序、错误类型/文本、重复依赖去重、输入不变及最后packed检查。

## 负结果与冻结验收

首版立即为稀疏图构建邻接表，producer.json显示512星形图慢21.29%，超过预设10%门槛，因此拒绝发布。core-v1.py和原始计时保留；v2改为观察两轮深度后再切换，并保持同一数值门槛。没有重跑v1挑选好样本。首版检查脚本第一次未在sys.modules注册git-loaded模块，导致dataclass装饰失败、尚未产生有效测量；修正harness后才测量。其错误原文在本次工具执行记录，未伪称远端保存了独立完整日志。v1旧harness未冻结完整快照，v1仅作诊断负结果；正式v2脚本与输入哈希由独立复核固定。

预先固定：512/1000深链中位数降低>=20%；1节点、512星形、1000密集图退化<=10%。每实现2warmup、9交错配对；小图每样本1000次，其他1次；构造在两者计时外，公开validate连同JSON序列化全部计时。生产者与独立者计时顺序执行，未与测试同时运行。无独占/锁频/绑核，保留全部离群值，不主张逐次调用都快。
