# 安装副本替换：并发目标所有权诊断

基线main `777f974ac98bb3a25ac8e468b0373cb036d4457e`；`setup.py`未改。主控和独审各执行一次固定四例，各为**2个安全断言失败、2个对照通过，0 error/skip**；子进程实际exit1原样保留。独审接受的是限定诊断证据，不是生产安全或修复验收。

| 时序 | 两次实际观测 |
| --- | --- |
| 旧副本备份后，并发创建空目标，再发布new | 无异常返回；空目标device/inode被新副本替换，出现新正文 |
| 同位置创建空目标，注入EIO后触发回滚 | EIO仍传播；空目标身份被旧副本替换，出现旧正文 |
| 无竞争正常替换 | 新正文正确，未报错 |
| 无竞争注入EIO | 旧副本原身份及正文恢复 |

这是一处普通路径rename的目标所有权缺口，在发布与回滚两个确定性时序中暴露；不是按失败断言数计算两个独立根因。各例只拦截暂存new到精确目标的调用一次，其余rename执行本机原生操作。原目标/暂存目录在占位目录创建前均已存在，身份比较在同例内成立，不以跨例复用的inode证明所有权。
