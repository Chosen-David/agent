## 候选比较与复杂度

- **采用A**：只保留本次已遍历且通过校验的请求根；访问V个可达唯一节点、
  R个请求根时，完整装配次数由V+R变成V。保持DFS顺序、每节点状态/文档
  校验和错误先后；存储请求根本就是最终返回所需，额外仅O(R)引用/键。
  非请求祖先不额外驻留；不降低原始DFS递归深度，也不宣称消除所有N+1。
- **暂缓B**：跨调用LRU/TTL结果缓存。它需同时跟踪纠错、状态、SQL和文档
  变化；本轮不扩展失效协议，避免旧通过结果被当成新验收。
- **暂缓C**：批量SQL装配/索引迁移。可能进一步省往返，但涉及更大的错误
  顺序与兼容面，当前先验证单个冗余因素，不混合归因。

模式是事务局部结果复用/图遍历，不是论文新算法，也不是GPU KV缓存。
已有PagedAttention知识卡的A100/服务并发前提不适用本地SQLite，拒作速度依据。
后续真实服务需明确已授权引擎、模型/模板/租户/cache格式与实际token输入，
再测冷/热、实际byte、完整请求质量与TTFT；本次不新建后台预取或付费服务。
