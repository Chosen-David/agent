## Problem, semantics and declared trust boundary (I–IV)

A restored workspace cannot revoke an already granted tool authorization or unsend a request. Distinguish workflow-call position x, underlying action d, new authorization, reuse, request transport, and returned effect. Copied calls may be different x but same d; retry is the same canonical request through a saved authorization link and adds no workflow-call event. A reused call still advances branch progress and can invalidate an edit candidate without adding to the authorization log. Matching authorization-log bytes alone is insufficient.

A task result here is an indexed complete alternative in a registered workflow, not a tool return or repository ResultStore record. Each requirement remains accounted for by preservation, already-satisfied status or removal signed by its original authority. Deleting an alternative can invalidate an edit even if the remaining execution obeys policy. In the normal/emergency example, policy permits yx and xz separately; their shared-prefix choices cannot jointly retain every compatible result. This differs from checking existence of one safe path or plain DAG acyclicity.

Finite pomsets preserve call identity/order. Indexed results may share identical residual traces and remain distinct requirements. Complete traces must be prefix-free; optional stop/continue needs an explicit registered terminal event. Choice uses tagged results; parallel and sequential composition use Cartesian results with disjoint call IDs, the latter adding an order barrier. C/w keeps compatible result identities and deletes processed calls/order edges. Processing means authorization or reuse, not remote service completion.

Execution record H includes policy-domain identity, immutable history DAG, current tree, signed checkpoints, versioned registered edits, call-to-action/canonical-request/scope/source correspondence, current rule entries, ordered call progress, state and rule versions. Current tree distinguishes open/selected choice, parallel/join and sequence. First processed call selects a choice even on reuse. Checkpoint checks freshID/currentbranch/exact residual registered contract, saves signed remainingwork and progress, increments stateversion, changes no active workflow or past authorization. It is not process-image checkpointing.

Assumptions are substantial: all tool calls pass through a trusted runtime; policy authority signs policies, source requirements and removals; registries/action identity/logs protected from Agent; one authorization record per action; canonical request equality and authenticated scope/token/source; queued transport respects new-authorization order; signed stable completion records from an idempotent or queryable service. Every state change and visible edit response in a policy domain uses a linearizable transaction that remains atomic across restart. Disjoint-domain composition requires disjoint actions, logs and policies. These are prerequisites, not benefits conferred by a prompt or local JSON receipt.
