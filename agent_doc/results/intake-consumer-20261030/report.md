# Intake consumer reuses the producer contract

`apply_intake` checked only that `questions` was a list. A directly supplied `intake/v1` request could bypass the builder's nonempty/bounded/question-field/unique-ID contract; an empty list could be returned as `CONFIRMED`. The consumer now obtains its normalized question list through existing `build_intake`, removing its weaker separate validator. The schema, answer/default/free-text/missing/unknown-ID behavior for valid builder output remains; inputs are unchanged. This is library completeness checking, not human permission or an interactive host implementation.

The frozen same-test comparison has 7 original and 4 new methods. Before repair, 9 `IntakeError` rejection assertions failed across 3 new methods, with zero errors/skips; these share one missing consumer-validation root cause. Producer repair and separate independent regression each pass all 11 methods, zero failures/errors/skips. Cases cover empty/21 questions, exact/normalized duplicate IDs, empty question text, duplicate/6 options, nonboolean free-text policy and invalid default. Controls retain JSON roundtrip, missing/default/Unicode free answers, full request/answer equality, and existing invalid/unknown-answer checks. Valid directly supplied optional-field/whitespace normalization beyond the roundtrip is supported by shared-source inspection, not separately executed new cases.
