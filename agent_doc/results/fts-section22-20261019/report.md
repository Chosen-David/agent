## 改动与研究应用

`agent_runtime/knowledge_index.py:205–209` 及 model-with-knowledge 插件镜像：
每节 lexical overlap 只算一次，保留计数，使用标准库 nsmallest(2) 精确取前两节；
随后按原规则排除零匹配。旧代码对获选片段重复分词，新契约测试修前记录 `2 != 1`。
这是一处性能浪费，不是已证实的检索正确性bug。key仍为(-overlap,start_line)，
900字符截断、FTS/RRF、预算、schema/engine版本和知识原文不变，无持久新缓存。
两份生产源码SHA256：8eb136aae4fab28b0f887c745e8d9e276948347a53af215e12659224b65c34d9。

[研究记录](research.md)复用既有12篇方法矩阵，并核查MemScope§3.1–4.4局部证据驱动修复、
Python官方小k精确选择。应用点是“局部源码定位→保持接口→同输入对照→独立复查”，
不称新发明排序算法、不将论文任务准确率迁移为本库收益，也不称本轮新精读12篇。

## 完整函数测量

Python3.12.14 / SQLite3.53.1 / Linux x86-64 / Xeon Platinum8573C（9逻辑CPU可见）。
固定PYTHONHASHSEED=0。每场景1对warmup后7个交替AB/BA pair，每个样本5次完整
indexed_search取每次平均wall毫秒；报告两臂中位数之比。包括连接、元数据/SQL、
RRF、对象复制/引用、片段构造；不含语料加载、建库及CLI启动。双方同store/只读DB。
基线完整模块由固定Git对象载入，依赖与当前相同；不是重写简化oracle。

主测14场景×7对×2臂=196计时样本（980次调用），独立复测12场景=168样本
（840次调用），各另有warmup和96项非计时边界对照。每个被计时输出与完整基线JSON
相等；种子DB字节未变。真实语料115条为总记录数，发布状态过滤照旧。
输入/代码/依赖/DB/输出hash与所有原始数据在raw.jsonl和independent-raw.jsonl。
