当前类型前提不足：task_id 在 core.py:45 用 isinstance(i, str)，接受 str 子类；依赖即使 type(d) is str，也不能保证 d 在 ids 列表中的相等比较与 d 在 set(ids) 中的哈希成员查询一致。一个内容为 "a"、继承 str、重定义 __hash__ 为与内置 "a" 不同哈希的 ID，可以在唯一性检查中通过；依赖内置 "a" 被原列表判断为存在，而集合查询不一定存在。还可能涉及自定义 __eq__ 的副作用与异常顺序。此为静态可触发设计反例，尚未运行复现，不能标实测。

返修要求：fast path 同时要求所有 ID 都是 exact builtin str，且当前依赖是 exact builtin str；任何 ID 为子类时，全部依赖保持原列表检查。不能通过新拒绝 str 子类来缩小接口。必须保留原 any(invalid ID) 短路在 set(ids) 之前，以避免提前 hash 非法值、改变报错顺序。保留非列表依赖的短路、逐字段验证顺序及最终 JSON 检查。
