# results：数据、运行记录与独立验证

这里保存当前项目可追溯的测试或实验数据、输入与配置元数据、产物清单、验证记录和结论适用范围。新数据按唯一 `<run_id>/` 分轮保存，供后续 AI 查找和判断是否可以复用。

生产者记录实际代码版本、输入、配置、环境、命令、原始数据、指标及单位，区分实测、推导和示例。每轮结果由独立的 `verify_experiment_result` 节点核验实际代码与数据；生产者自报成功、退出码为零或文件存在，都不能替代独立验收。

- `pending`：仍缺有效独立验证，不能支持下游正式结论。
- `usable-with-scope`：仅能在记录的条件与范围内使用，不表示适用于任何环境或绝对无错。
- 失败、缺失或过期：保留原始记录，修复后以可追溯的新版本重测、重验，不覆盖失败来制造成功。

收到新任务先检索已有结果，再比较目标、代码、输入、配置、环境、指标单位及当前验证状态。条件不匹配时说明拒用或需要补验的原因；用户明确要求复现及新主张必需的验证仍需完成。

历史冻结目录、原始数据和 manifest/record 保持原样，不为补目录说明批量改写。`../legacy-result-paths.json` 仅登记历史旧路径的只读定位，不授予当前验收。公共知识库在工作流仓库 `knowledge/`，论文结果不能冒充本项目实测。私密数据与高频机器状态按项目约定保存，不能顺带提交公共仓库。

任务与结果的对应关系写进 [task 详情](../task/README.md)，汇报说明结论、证据及限制。
