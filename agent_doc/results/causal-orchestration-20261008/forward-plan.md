## 4. 独立验收、D1图与全集汇合

实验前冻结每项验收的 procedure、acceptance、allow_not_applicable。不得看过结果后改阈值。六项检查分别为：

1. implementation：读实际执行代码和分支，核对 eval 状态、dtype、索引、异常路径及共享状态隔离。
2. reference_boundary：独立指标重算、小规模可信参考及空输入/异常标签/边界用例；参考不复用同一错误实现。
3. data_integrity：逐样本 ID 全集、唯一性、标签对应、重复/缺失/失败记录、版本与 seeds，恢复片段不得混入旧协议。
4. numerical_sanity：准确数是合法计数、`0≤ci≤ni`、有限值、准确率在[0,1]、单位明确、原始输出与汇总一致。
5. measurement_validity：核查划分、指标分母、采样/批量等价、训练测试泄漏和数据集间选择泄漏；本轮没有性能主张，性能子检查才可预先允许 N/A，准确率有效性检查不可省略。
6. reproducibility：按冻结配置、样本与种子独立小规模重跑/交叉核查；需要的检查若缺资源则 inconclusive 并阻塞，不伪装 N/A。随机模型的重复规则、容差及统计单位必须预先在 P 明确。

生产完成只产生 pending；独立检查通过且证据/版本绑定有效才为 usable-with-scope。检查不通过是 invalid，证据或 verifier 不足是 pending。验收记录由真实独立提供者出具，保存实际审查身份、事件、原始证据及 limitations；自写 pass、仅换 owner 名或文件 hash 都不证明独立正确性。当前通用验证器若受16 MiB/文件限制，需完整有界分片或核实项目大数据适配，不能用摘要替代全量覆盖。

D1图只消费 C1，默认显示 D1 准确率及 `c1/n1`，标“仅D1，其他数据集未汇合”；没有冻结重复实验和有效统计模型时不虚构误差线。图的派生数值通过 VA1 才交付。不得把图当八数据集趋势、全局模型选择或提前总排名。

JOIN8 放行条件：恰好八个数据集、每个恰有一个适用且独立验收通过的最终契约；检查样本/分片完整覆盖、数据集身份、无意重复、相同 M/P/code 等必要指纹、计数单位和分母规则。不同数据集合法的同名本地 ID 使用 `(dataset_id,sample_id)` 区分；真实跨数据集重复须在冻结 P 中明确处理和披露，不能悄悄去重或重复权重。

若 P 为每个样本一次可判定准确率，`ni` 是冻结规则下的评测分母，`ci` 是判对数，`ai=ci/ni`：

\[
\operatorname{macro}=\frac{1}{8}\sum_{i=1}^{8}a_i,\qquad
\operatorname{micro}=\frac{\sum_{i=1}^{8}c_i}{\sum_{i=1}^{8}n_i}
=\frac{\sum_i n_i a_i}{\sum_i n_i}.
\]

不同大小数据集不能用无权平均准确率冒充 micro。保存各 `ci,ni` 和原始记录；若 P 含重复/权重，必须先冻结相应 estimand 与充分统计量，再按该单位聚合，不将相关重复自动视为新独立样本。`ni=0`、缺项、非法分母或评测错误不能静默丢弃；按预先规则处理或阻塞，不能事后改分母。标准差不能直接平均。汇总本身也须独立重算验收。7/8 时只可报告带覆盖率的进度，ACC8未完成，不能把D3改为可选。

## 5. D3失败、恢复与取消

1. reconcile原提交账本及真实作业状态：如果只是客户端超时/网络断连且作业结果不明，先查询原 job；pending 就 poll 原 job，不提交第二份。确认实际终止、资源释放后才允许D3重试。
2. 定位是暂态基础设施失败、输入错误、代码/协议问题还是经识别的 OOM；只有对应受影响分支可修复。若发现共享代码缺陷，隔离所有受影响结果/下游结论，逐项分析传播范围，继续真正独立且适用的工作。
3. 本规划建议每数据集最多2次生产尝试（初次＋1次），因此D3剩1次；每次失败也计入已用预算。恢复/验证检查同样有宿主冻结的有限时间/次数预算；总墙钟/GPU-hours/费用未知，执行前须填写并认证，不能以此建议自授算力额度。题设“继续”允许推进独立工作与有界恢复，不是无限重试。
4. 新尝试 `E3-a02` 使用新的实际 run/result ID和 `Rnew/D3/a02/`，不覆盖a01；独立 `V3-a02` 验收。失败诊断与修复、新契约及替换依赖形成不可变计划新版本，绑定旧lineage和历史，按工作流重审核；不得静默改已有DAG或靠换ID重置预算。独立在跑分支按仍有效原批准范围继续，不重提交。
5. 仅当检查点完整且 M/P/code/data/seed/样本ID与输出指纹兼容、恢复适配器确实支持时复用已完成样本；否则只完整重跑D3，不拼接不兼容片段。旧成功分片复用还需核实当前契约适用性与独立验收绑定。

## 6. 对两个追问的直接回答

**同一可变模型从D1顺序微调至D8不能把八段训练当独立评测并行。** 若 `M1=train(M0,D1)`、`M2=train(M1,D2)`，后一段使用前段验收后的checkpoint及优化器/调度器/RNG状态，存在真实因果链 `T1→VT1→T2→VT2→…→T8→VT8`。同一模型/优化器并发写还会产生竞争与不同算法。可并行与前序权重无关的数据准备，或对已冻结checkpoint做独立评测；训练内部数据/模型并行需另审方法与多卡资源组，不能据此宣称八阶段并行。八个从M0出发的独立微调副本是另一实验，需另目标/协议/预算，不能替代要求的顺序轨迹，更不能替换本轮固定M的八项准确率基线。

**准确率并发期间记录的时间不能直接称为该方法单卡无干扰延迟。** 一卡一作业仍可能共享CPU、加载、RAM、I/O或网络；排队/加载/验证更不是纯计算延迟。本轮可真实记录每阶段时间及准确率任务吞吐/makespan，明确并发资源条件；没有测量就不报数值。

若未来要单卡延迟，另建经授权与独立审核的性能链，等待可比条件与可信宿主的真实GPU排他分配和共享瓶颈隔离，固定GPU型号、CPU/线程、输入shape/长度分布、batch、精度、协议、软件和热/缓存条件；区分冷启动与warmup后稳态，按声称口径同步/使用正确events，预设重复、配对/交错、停止条件并保留全部样本及离散程度。24GiB卡不能承担原32GiB工作负载，因此若要八项同硬件比较须选择有足够容量的卡并明确可比范围。A/B/C容量信息不证明型号或速度相同。当前未授权/未执行这个附加性能实验。

准确率流水的端到端账应分记排队、启动/加载、计算、验证、绘图/汇总、makespan、GPU-hours、失败和返工，不能把墙钟缩短等同于算力/费用下降，也不由三张卡推导三倍提速。
