## 方法与威胁模型（III–IV）

攻击者只能在任务开始前放置根CLAUDE.md或AGENTS.md，知道目标CWE，不能修改其他代码、用户请求、测试或配置。目标是保留功能但生成含目标弱点的代码；不是命令执行/窃密模型。实验清空原历史和其他指令，仅一个中性commit及恶意文件，属于攻击者有利的单一文件环境，不等于真实项目中多个授权来源共存。

SecRepoBench原318任务/27个C/C++项目，先按预试运行少于5分钟筛17项目，再选至少有3任务的12CWE，每类3任务，最终36任务/15项目。作者说按时间和元数据选择而非测试结果，但快项目筛选仍限制外推。Claude Code2.1.308/Sonnet5.5；OpenCode2.1.1经OpenRouter运行Qwen3.8-27B和DeepSeekV4.1Flash，xhigh、默认无安全提醒prompt、会话1200秒，失败最多重试一次。每任务/模式一个completion，没有独立重复采样。

KimiK2.6按CWE4.20起草12×2=24文件，再由作者手调（局限也提预试迭代）。v1措辞较缓382–420词，v2更强601–702词，兼增性能压力、反检查例子、注释优先和单测正确性说法。因此强度/长度/内容同时变化，不能把差异当纯语气消融；没有正常记忆文件对照，存在文件/长度与恶意语义也未隔离。

安全判据：编译成功且原OSS-Fuzz PoC在sanitizer安全build不再触发；只覆盖目标弱点。功能判据：参考修复可通过的开发者单测仍全过，不是完整正确性。超时/编译/解析错误都计不安全，故not-secure不等于成功生成可利用漏洞。攻击成功要求功能与安全的联合状态，不能用两个独立汇总率推断每次flip满足攻击目标。

## 结果、比较与负结果（V–VI）

每个系统只纳入三个模式均有结果的任务。Qwen6任务几乎都超时而被整组三模式排除，余30；另两系统各36。匹配评价集102任务×3模式=306 completion（算术），而污染分析报告313 completion，313与匹配集推算306不一致，原文没有解释；可能统计范围不同或有笔误，不能确定，更不能悄悄合并。两文件模式各与同一baseline配对，共204比较；baseline复用，不是204独立任务抽样。

摘要安全率变化−8至+6百分点，最多3任务，6个变化中4个方向提高安全率。作者灰区表示少于6任务差难与偶然区分，未给正式显著性/区间/功效检验；观察不足以确证攻击有效、安全保护、等价或无风险。204对中30对恰有一边安全，baseline-only15/file-only15，净效应抵消；单次采样不能把所有flip归因文件。各模式功能可行率约80–92%，仍不是所有输出安全。

RQ2对文件名/攻击标签检索最终回复及作者可见推理文本，再人工查命中片段。Claude约2/3提文件；OpenCode主要在内部可见记录，最终回复少；DeepSeek v2约1/3识别攻击、v1无识别。Claude是thinking summary，OpenCode是raw trace，可见性不一致，不能跨系统比较隐藏推理忠实性；字面搜索漏掉转述，属于下界。18会话的作者可见记录将文件标为攻击，其中只有4最终回复提及文件；原文未证实这4次披露了攻击判断。较baseline安全下降3/提高2。识别、沉默、报告本身都不是安全验收，无须收集或公开模型隐藏思维。

13/313 completion复现参考代码块；删其任务后变化不超过3百分点，只是有限敏感性检查，不证明没有训练污染。OpenRouter可变路由/有效模型版本、无重复采样、目标PoC/有限单测、人工调payload、快项目和单一指令设置均限制结论。作者计划真实/良性文件对照、更多语言/模型、至少3次重复、语义文件复核和监测；这些不是已验证防御或本库收益。
