## Why this resolves the earlier design objection within its stated scope

`ReportingHandler.run` currently validates results at entry, performs actual lookup/review, invokes its sole `context.current()`, checks memory/knowledge/documents, and invokes the handler. Its post-action result gate can reject only after work has started. `inspect_result` calls a trusted verifier and rechecks that individual result's snapshot/evidence. `check_task_reuse` invokes `decide_run`, which independently inspects again. These are potentially blocking callbacks. Actual `Context.current` checks cancellation, token, doing status, and lease against its clock.

The proposed ordering is adequate for a narrower deterministic claim: entry checks remain; after lookup/review, obtain new independent result and reuse proofs; after **all** those callbacks finish, check the claim once; then passively recheck **all** captured proof/registry bindings and revocation, recheck reuse age, and perform existing memory/knowledge/document checks before calling the handler. No verifier or adapter callback may be introduced after current. This catches callback-induced changes to captured evidence, including a later result verifier changing an earlier result. It also places verifier-induced claim expiration/cancellation/token loss before the existing claim gate. It does not certify lease validity after passive I/O, concurrent filesystem mutation after a checked read, a global snapshot, host fencing, or atomic external effects. Those limitations are explicit and acceptable for this repair.

## Exact proposed helper inspection, first bytes

Inspected `proof-helper.txt`, `age-helper.txt`, `reuse-helper.txt`, and `dispatch-block.txt` without executing them. **REVISE these exact helper bytes**, retaining conceptual approval of the direction:

1. `_check_validated_bindings` must start by normalizing `root = Path(root).resolve()` (or equivalent at the common boundary). Unlike `inspect_result`, it currently passes the root directly into `_bound` / `assert_not_revoked`. `ReportingHandler.__init__` preserves its supplied root, and existing public gates accept string roots. `_path` performs root/path arithmetic and expects a Path; passing a string introduces a TypeError that the new dispatch catch does not handle. Preserve the supported string-root path, with an unchanged dispatch control exercising it in the frozen tests.

2. `_measurement_age_reasons` currently calls `dt.datetime.now` internally. This is one shared rule but is not the promised pure age-policy helper. Supply its evaluation instant as an explicit value captured at each caller; parse explicit `decide_run(now=...)` with existing `_timestamp` behavior and preserve no-age / missing-unbound-time short circuits. A timezone-aware datetime instant is a suitable internal value; `_timestamp` itself accepts ISO8601 text, so avoid feeding datetime objects into it accidentally. The post-current caller needs a new instant after current. This does not authorize any callback or trusted-verifier adapter after current.

The remaining exact ordering is sound for the bounded claim. Rechecking `dispatched_task` is appropriate: it is the existing deep copy produced before the fresh callbacks and is the object actually passed to the handler. A host callback that mutates the original task cannot silently switch dependencies checked here. Keep original post-action/report gates as planned; this change makes no broader guarantee about arbitrary callback mutation of unrelated task/host state.

The live reuse proof originates inside `decide_run`, which already checks the registry/manifest correspondence; pinned unchanged registry SHA plus the same invocation's nested proof preserves that correspondence under the stated live-only caller contract. No fake-verifier replay is present. The helper checks manifest, artifact hashes (including plan), review evidence, and result/run revocation without new verifier calls. The final required-result loop occurs after both callback-producing gates, so later reuse callbacks can be caught invalidating earlier required results. Exact fixture/module review remains pending.
