## Mechanism, experiments and limits

A source/goal/budget compressor cannot see its evaluation questions; one compressed text serves all questions under that goal. A fixed DeepSeek-V4-Pro reader/judge evaluates ten compressors. Micro counts correct questions; Macro counts goals with every answer correct. Full data contain 500 goals; goal ablations use a distinct 124-goal, paired-goal subset. Own/no/alternative-same-source goal conditions separate target guidance from mere topic hints. Length uses cl100k_base; oversized generations are prefix-truncated, not regenerated. Thus retained length is not provider-native usage or full compression cost. Main scores have no reported repeat uncertainty; mechanism comparisons change compressor backbones and goal signals. Judge agreement is 112/114 sampled responses, not universal correctness. Curated full-context answerability and fixed-reader selection limit generalization. This is offline question answering over documents/traces, not successful execution of a live code task. Adopt complete-goal coverage as a future diagnostic; reject copying silent prefix truncation into complete-context interfaces.

## Current repository audit and decision

Existing `Mailbox.prepare_context` consumes a validated handoff before `basis_context`. That builder retains declared ancestors, required refs and candidate/rejected claims, then refuses an over-budget complete basis. It explicitly leaves semantic relevance unchecked and treats known IDs as host assertions of current-context possession. Its tokenizer counters cover the serialized payload only; envelopes, output and all actors remain separate. No new semantic-completeness guarantee follows from valid references or a lossless encoding.

`prepare_dispatch` emits a plan rather than making model calls; the source/selection layer and actual host consumption remain separate. The prompt composer has real CLI and token-probe consumers, but `token_probe.py` is a narrow fictional reading probe with its own authenticated quota admission, provider usage and platform process requirements. It is not an end-to-end project-task benchmark. No existing admission/configuration is inferred or reused to launch it here.

A real ResultStore query is recorded in inputs.json/private exact output: lexical candidates plus incomplete/error status, not accepted task-quality evidence. Candidate summaries distinguish CPU/SQLite/display work from model quality; no stored pass label is promoted or external SGLang material accessed. Search truncation/errors prevent an absence claim.

Keep unique TASK, MemoryLedger, directed handoffs and fail-closed full-context budgets. No new memory layer, shared chat pool, context truncator or agent_doc migration is justified. Future paired task-pack/full-source acceptance must check current user goal/authority, cancellations, corrections, objections, dependencies and actual terminal outcome; offline all-question accuracy is only one diagnostic. Model input/output/cached/provider totals and every actor's cost need actual matched receipts, never file-size estimates. The necessary matched consumer protocol and authenticated accounting are not established by this source audit, so that quality/cost conclusion remains blocked.

No production changes, tests, model benchmark or performance claim this checkpoint. Actual root/reviewer AI inference happens; complete provider accounting is unknown, not zero.
