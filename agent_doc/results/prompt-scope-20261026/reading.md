## Paper mechanism, controls and limits

Temporally filtered repository PRs exclude solution leakage; relevance labels distinguish actionable transfer from incidental overlap. Historical trajectories build frozen, read-only memory before independent target trials. Main evaluation uses one Claude Code/DeepSeek configuration on Verified Python tasks: 133 improvement and 50 preservation targets, three history scenarios, three runs. Fresh NoMem trials differ from subset-selection trials. Relevant history still causes regressions; noisier history can offset rescues. FullTraj reduces steps while increasing input tokens. H.1 excludes historical memory-building tokens; infrastructure-error retries are rerun. Rescue/Harm use all nine cross-condition outcome combinations, not nine independent tasks; bootstrap resamples tasks. Gold-edit overlap is not functional correctness. Failed-trajectory attribution is manual and nonexclusive, not a randomized ablation. D proposes state-specific environment rebuilding and validated reuse; the paper explicitly lacks systematic pipeline comparisons. Thus preserve executable evidence and applicability checks, but do not infer that full-history replay is cheapest or that semantic transfer is solved.

## Repository interpretation and current change

`ResultStore.search` retrieves candidates; `decide_run` requires matching explicit conditions plus current independent scoped acceptance. Historical records stay unknown and cannot authorize skipping new-claim execution. `check_handoff_basis` explicitly leaves scientific applicability unchecked; `check_task_memory` checks declared ledger references. These are useful controls, not model-quality guarantees. Existing unique TASK, MemoryLedger and directed handoffs remain authoritative; no new memory layer or shared chat pool is proposed.

The prompt composer promises to retain unverified scopes. Its remaining splitlines fence loop can invent global scope from a literal Unicode suffix. The proposed fix aligns that loop with the existing Markdown physical-line helper and fixes actual CLI UTF-8 materialization; neither parser equality nor passing fixtures certifies model task quality. Adjacent log/artifact roundtrip formats retain their current contracts. The source view already uses AST physical lines.

Adopt the evaluation distinction between preservation and rescue for future actual task comparisons; defer a new model benchmark until a matched consumer protocol and complete resource/provider accounting can be supplied. Record compatibility and correction failures separately, keep failed evidence, and evaluate actual final outcomes rather than proxy edit similarity. This paragraph is repository planning, not an implemented benchmark or new permission. Old exhausted fullsuite/PID/ALIAS/role/Codex/wire gates remain unchanged.
