# SYSTEM-99 阶段Q：确定性结果目录扫描方案

基线 `2c691878ccff1bf1461ffdda0a235f2869de2e3c`。本阶段修复现有
`ResultStore.search` 的有界扫描成员不确定性；不迁移 `agent_doc/results`，不改变
`record.json` schema，不给旧结果重新授信，也不把剩余12个非标准目录静默排除。

## 修前事实与根因

`ResultStore._directories(max_scan)` 当前按 `os.scandir` 的文件系统原生顺序计数，达到
`max_scan` 就停止，最后才排序已经选中的名字。后果是：

1. 同一三条合法记录、同一查询和 `max_scan=2`，只反转枚举顺序，命中集合可由
   `alpha,middle` 变为 `middle,zeta`；两次都报告 `scanned=2, partial=true`。
2. 根目录普通文件也消耗扫描名额。当前树有252个结果目录和一个 `README.md`，默认
   `max_scan=200` 实际只检查199个目录。
3. 截断后的目录名、符号链接和坏记录没有被观察；`partial=true` 会阻止完整无命中声明，
   但不能使候选集合、错误集合或查询漂移比较在不同文件系统顺序下可复现。

修前反例使用临时根、真实 `register_history` 记录和仅改变返回顺序的 `os.scandir` 包装；
不修改仓库结果。当前树1000次纯枚举基线中位数为79.399微秒、p95为113.731微秒；完整
枚举后排序原型为92.680微秒、p95为123.025微秒。该数字只衡量本机目录枚举，不是完整
检索或模型性能。

## 有界修复（Version24返修）

修改 `agent_runtime/result_store.py::_directories` 与 `_save`：

- 最多观察5001个顶层条目。若出现第5001项，返回空成员集、实际观察计数和 `partial=true`；搜索因此只能
  得到 `incomplete`，登记仍因partial拒绝。绝不从一个超过全局上限的原生顺序前缀返回候选。
- 在不超过5000项时检查全部条目的符号链接和目录标识符，收集全部目录名并排序；然后才取
  字典序前 `max_scan` 个目录。`partial` 只表示目录数超过 `max_scan`。
- 根目录普通文件计入5000项安全上限，但不消耗 `max_scan` 的结果目录名额。
- 保留 `max_scan` 的1..5000输入边界、记录读取/错误可见性、候选排序、unknown/验证和只读语义。

`_save` 同时纳入容量边界。所有协作登记先在结果目录之外的
`.agent-runs/result-store.lock` 取得跨进程互斥；该本地运行状态路径已被git忽略，不参与结果扫描。
锁文件以不跟随符号链接的普通文件FD打开，Unix使用`flock`，Windows使用首字节`msvcrt.locking`；
进程正常、异常或被终止时FD关闭并由操作系统释放锁。持锁后重扫并完成大小写冲突、全局项数与
目标目录存在性判断：目标不存在且当前已5000项就直接拒绝，少于5000才创建目录；目标已存在时
不增加顶层项，恰好5000项仍允许补 `record.json`。锁在目录容量预留完成后释放，文件哈希和最终
不可覆盖硬链接不占用全局锁。同run并发仍由最终硬链接决定唯一发布者。

因此不同run并发从4999项开始时，最多一个能创建第5000项；另一个随后持锁观察5000并拒绝，
运行期间也不出现第5001项。进程在创建第5000项后崩溃最多留下一个显式缺record空目录，不会
越过容量；后续检索fail-closed，人工或同run恢复可处理。这里保证参与该接口的本机进程硬容量
上限和不覆盖，不宣称跨主机共享文件系统或绕过接口的直接目录写入也受该锁约束。

不增加忽略清单或特殊目录类型。纯计划、活动目录、父容器、混合身份和超64文件包仍按现有
规则显式出现在完整扫描的错误中；阶段Q不解决它们的身份/分片设计。

## 验收

先新增修前失败回归，再改生产代码：

- 三条真实record在正向/反向模拟枚举下，`max_scan=2` 都只选择字典序前两项；
- `README.md` 加两条record、`max_scan=2` 必须扫描两目录且 `partial=false`；
- 符号链接即使位于搜索截断项之后也拒绝；
- 模拟5001个安全普通条目时返回空成员和partial，不泄露顺序相关候选；
- 4999项新增目录成功并达到5000；5000项新增目录拒绝且无残留；5000项已有目标目录仍可补
  `record.json`；不同run并发期间观测到的最大顶层项数不超过5000；持锁进程异常退出后另一进程
  能取得锁；
- 原有坏record、扫描截断、缺store、大小写冲突与注册原子性回归保持；
- 当前树固定查询在同一代码/输入下重复输出逐字节一致；记录默认200与完整5000两种范围，
  不把候选差异当召回质量提升；
- 运行ResultStore/复用定向、全库、Reader和同步检查，再做独立结果验收。
- 阶段F集成回归证明候选/errors/partial变化仍阻断受保护producer；仅完整无错且除scanned外完全
  相同的变化才可继续。

若独立方案审查发现排序语义、5000项上限或下游漂移协议冲突，先升级本方案和SYSTEM-99版本，
不实施旧版本。发布前fetch；main漂移则重放修前反例和受影响验收，不强推。

本阶段只主张确定性与安全边界修复。没有模型质量、token、费用、完整检索吞吐或整批完成主张；
真实宿主/多轮任务质量、12个非标准目录及其长期组织方案继续open。
