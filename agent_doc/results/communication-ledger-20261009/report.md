# 通信预算增量计账：验收报告

基线：`bb5bf5b8edaebd8910f9a7af28830c668113d339`。本轮将每次publish的历史COUNT/JOIN/SUM替换为随事件事务维护的每run账本；保持消息、路由、文件校验、重试、ACK和预算语义。初次打开旧库自动原子回填，兼容旧Mailbox的append写入。

**结论：冻结的高历史量目标通过，属于本地通信运行时优化。没有LLM质量、token、网络流量或任务总耗时A/B；不是新论文算法。**

[独立原始记录](independent-clean-raw.json)、[核验绑定](independent-validation.json)保留代码/计划/基线hash；独立SQL重算、旧连接升级、回滚、并发cap等检查通过。先前与测试重叠的独立计时单独保留，不拿来作为无争用复测。其他云宿主噪声不可排除，不能把各规模倍率推广成稳定SLA。

## 代价和边界

- publish观测退化：n0-f8-budget0 +3.95%；n100-f1-budget1 +0.89%；n100-f8-budget0 +32.54%；n1000-f8-budget0 +11.80%。全部保留，不声称普遍提速。
- usage观测退化：n0-f1-budget0 +16.87%；n0-f8-budget0 +34.14%；n0-f8-budget1 +1.41%。全部保留，不声称普遍提速。
- reopen观测退化：n0-f1-budget0 +11.93%；n0-f1-budget1 +28.96%；n0-f8-budget1 +0.71%；n100-f1-budget1 +29.74%；n100-f8-budget0 +32.25%；n100-f8-budget1 +0.69%；n10000-f8-budget0 +10.03%。全部保留，不声称普遍提速。
- 主目标初次打开/迁移：原扫描0.820 ms，账本119.817 ms；一次观测，未估计迁移延迟分布。迁移持写锁，大库应预留窗口并做一致性备份。
- 追加维护增加小负载写入成本；大引用文件校验、模型推理或外部工具可能主导总耗时，本轮没有加速这些阶段。
- 支持现有Mailbox追加/ACK API，不支持任意SQL修改或删除历史、REPLACE或破坏触发器；同权限恶意数据库写者仍在可信边界之外。
- 累计预算不因ACK退还；重复重试不重复计账；预算检查与整个fanout在同一事务，失败不留下部分消息。
