# Task/advice literal source-line preservation

SYSTEM-99 remains open. This checkpoint repairs two existing consumers in place; it adds no memory layer or parallel implementation. Exact plan and frozen independent feedback are in plan.md and plan-review.md (v1 preserved as plan-v1.md).

Canonical TASK parsing already uses Markdown CR/LF/CRLF physical lines, but task_view used Python's wider splitlines. A Unicode separator followed by an OLD-shaped row silently removed literal global instructions; an invented fence instead retained an unselected row, and separators in task titles corrupted row deletion/source positions. Advice topic discovery had the same mismatch: an H2-looking suffix cut global or selected text, while a pseudo-fence suffix caused rejection. Both now reuse existing project_docs.physical_lines with terminators preserved; current selection/fence grammar, schema, source SHA, budgets and all error gates stay intact. The shared helper itself is unchanged.

Baseline original production SHA and exact regression inputs are bound in baseline.json. One baseline invocation ran 19 methods and observed 88 failing and 24 error subcases; these counts are subcases, not 112 distinct production bugs. Fixed invocation ran 103 methods across eight named modules, all passed without skips. Their raw output is baseline.log/fixed.log. Different suite sizes and unittest elapsed times are not a performance comparison. run_checks.py records before/after hashes; both invocations observed stable bound inputs.

Six new regression methods use original physical chunks as their independent oracle (not the helper). All eight nonphysical separators remain literal content; LF/CRLF/CR, EOF without newline, fake row/H2/fence suffixes, selected/unselected titles, exact source-line maps and complete leading/selected text are checked. Actual subprocesses exercise task selection plus advice discovery/topic selection under conflicting cp936 parent output settings, decoding UTF-8 and confirming unchanged source bytes. Existing stale/unknown/ambiguous/comment/budget rejection tests remain unchanged. CI now invokes both existing test modules in the current Ubuntu/Windows × Python3.10/3.12 installation matrix; actual native run results must be read separately after publication.

Independent result acceptance belongs in result-review.md, with its own raw invocation and hashes. This report does not itself grant acceptance. Root and reviewer use actual AI inference; complete provider usage/cost is unknown, not zero.
