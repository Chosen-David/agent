# 双主 AI 架构建议 v1

- Author category: AI proposal responding to the user's 2026-10-07 request for two main AIs, one planning and one reviewing. This is advice, not a human guide or tool authorization.
- Task refs: DUAL-01, DUAL-02, DUAL-03.
- Decision: adapt. Adopt separate planner/reviewer invocation and exact full review feedback; require a trusted host boundary, complete executable-plan hash and explicit finite revision budgets. Keep current specialist roles, result validation, document authority and publication permission.
- Evidence: existing runtime already has immutable DAGs, current-document checks and independent result verification; it did not provide an independently authenticated main-plan review receipt at dispatch. A second self-declared prompt pass does not close that gap.
- Primary source: [Humanize RLAR](https://github.com/humanfia/humanize/blob/85e755543b14920bf053be01cdc5229aefe13972/src/hmz/flows/builtin/rlar/__init__.py) at commit `85e755543b14920bf053be01cdc5229aefe13972`, and [The Review Is the Next Prompt](https://humanfia.ai/blog/2026-08-17-the-review-is-the-next-prompt). Useful engineering mechanism: a continuing actor receives a fresh independent review, with full feedback and a separate compact verdict. This is an upstream design example, not measured performance in this repository.
- Primary source: [KDA agent flow](https://github.com/NVlabs/kda/blob/ef6ce617693ef0782b3ecb9f37e39bbf10226a90/docs/agent-flow.md) at commit `ef6ce617693ef0782b3ecb9f37e39bbf10226a90`: explicit contracts and correctness before optimization/promotion. Retain the existing implementation workflow rather than introducing an unrelated optimizer.
- Rejected: silently accepting role labels/JSON approval, rewriting user intent or guide, bypassing host approvals, unlimited actor/reviewer loops, requiring a new provider or claiming a live two-model backend from prompt installation.
- Deferred: relay/topology changes, token/quality A/B claims, new model/API/GPU deployment. Reopen only for an explicit bounded task with suitable host access and controlled measurements.
- Validation: exact-plan stale/forged/replayed/self-review/advice/evidence negatives; post-effect revocation cannot replay an effect; CPU producer→independent data verifier→consumer; real separately observed native-plan review material is distinguished from automatic LLM deployment.
- Known limits: hashes bind bytes, not semantic truth. The host authenticates actual invocations and user authority. Review ledger is application state, not an OS sandbox. CPU protocol tests do not estimate model quality or cost.
