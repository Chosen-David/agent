# 突发任务服务包络与延迟边界

任务 MATH-58；候选稳定 ID：`candidate.burst-service-envelope@1`；版本 1，2026-10-09。这是任务级数学候选及实验设计，未发布为知识卡，未接入生产调度器。来源定位与检索输出见 `../results/math-burst-service-20261009/`。

## 为什么需要这个结构

“平均提交速率低于平均处理速率”无法给出最坏排队延迟。突发提交、模型加载暂停、跨机传输、其他用户争用，都会打破用一个平均 tokens/s 推算 deadline 的做法。正确结构是：同单位的累计工作量、任意时间窗口的到达上界，以及系统实际承诺的服务下界。预测耗时仍可用于方案排序；保证未知时必须保留 unknown。

## 数学对象与前提

采用从空系统开始的连续流体模型：累计到达工作量 A(t)、完成工作量 D(t) 非负、连续、非递减，A(0)=D(0)=0，D(t)≤A(t)，无丢弃。离散不可抢占作业不能自动照搬流体保证，需另证包含最大作业阻塞/完成量跳跃的服务曲线。初始积压需要显式加入到达与初始状态，不能忽略。

到达包络要求 **所有** 0≤s<t：

\[
 A(t)-A(s)\le\alpha(t-s),\quad
 \alpha(h)=\sigma+\rho h\ (h>0),\quad\alpha(0)=0.
\]

服务曲线是系统对该工作流的保证，**所有** t≥0：

\[
 D(t)\ge\inf_{0\le s\le t}\{A(s)+\beta(t-s)\},\qquad
 \beta(h)=R(h-T)_+.
\]

σ≥0 是工作量单位的突发上界；ρ≥0 与 R>0 是工作量/秒；T≥0 是秒。R 不是平均速度，T 不是观察到的平均加载时间。定义积压 B(t)=A(t)−D(t)，虚拟延迟 w(t)=inf{d≥0:D(t+d)≥A(t)}。FIFO 下可解释为到 t 已到达流体的完成延迟；非 FIFO 不能推出每个任务没有饿死。

经典依据：Le Boudec/Thiran，*Network Calculus*，Springer LNCS 2050 (2001)，Definition 1.2.1、1.3.1，Theorems 1.4.1–1.4.2，Figure 1.10（印刷页 7、19、22–24）。作者 [PDF](https://leboudec.github.io/netcal/latex/netCalBook.pdf) 当前版本精确修订日期未确认，下载 SHA-256 记录于 sources.json。以下为该模型的独立特例推导，不把工程预测标为教材定理。

## 可复核证明

若 0≤ρ≤R，则：

\[
 B(t)\le\sigma+\rho T,\qquad w(t)\le T+\sigma/R.
\]

由服务不等式和 a−inf f=sup(a−f)，

\[
 B(t)\le\sup_{0\le s\le t}[A(t)-A(s)-\beta(t-s)]
 \le\sup_{h\ge0}[\alpha(h)-\beta(h)].
\]

h=0 时差为 0；0<h≤T 时差为 σ+ρh≤σ+ρT；h>T 时差为 σ+ρT+(ρ−R)(h−T)≤σ+ρT，得到积压界。

取 d=T+σ/R。对于 0≤s≤t，令 u=t−s；β(u+d)=Ru+σ≥ρu+σ≥A(t)−A(s)（s=t 也成立）。对于 t≤s≤t+d，A(s)≥A(t)，β≥0。因此服务表达式在 t+d 的每一项都≥A(t)，其下确界也≥A(t)，即 D(t+d)≥A(t)。不需假设下确界取到，得到延迟界。

σ=12 工作单位、ρ=2 单位/秒、R=4 单位/秒、T=1 秒时，积压≤14 单位、虚拟延迟≤4 秒。这是解析算例，没有仿真测量。ρ=R 时界仍有限，但无速率余量，稍差的服务就不能沿用；σ=ρ=0 且空队列实际延迟为 0，给出的 T 界不一定紧。ρ>R 时取 A(t)=ρt、D(t)=Rt 的持续饱和流体服务器，积压=(ρ−R)t 无界；这是允许的反例，不表示每个超包络参数的具体流都会爆炸。

## 拒用与误用反例

- 平均到达率很低，但先提交任意大的有限突发 N 再长时间空闲：延迟 N/R 可任意大。均值不能代替固定 σ。
- 观察吞吐稳定但未来可能无限暂停：无法提供固定 T 的服务保证。历史均值或 p90 不证明全窗口包络。
- 两张卡各自速度 4，但目标模型只兼容其中一张：不能给该模型 R=8；实际可用的服务不能由卡数相加。
- 按 tokens 计数混合不同 prefill/decode、上下文长度、模型和 batch：工作单位的代价不一致，不能直接用一条 R。
- FIFO 不成立时，累计完成量跨过 A(t) 不代表某个具体旧任务完成。工作积压也不是 VRAM 字节数，不能直接作为显存准入界。

## 具体迁移与轻量接口建议

| 项目对象 | 理论对象/保留关系 | 成立证据 | 不保留的因素 |
| --- | --- | --- | --- |
| 固定部署、形状桶内的有界工作块 | A、D，同一工作单位且无丢弃 | 实际准入限流、已计入初始积压 | 普通 token 不自动等工作量 |
| 为一条 FIFO 队列保留服务 | β 与所有窗口下界 | 资源预留、最大暂停/阻塞有工程依据 | 预测器输出不构成预留 |
| 传输链路字节队列 | bytes、bytes/s，严格量纲映射 | 流量整形与链路保证 | GPU 内存不是链路积压 |
| 多机 DAG 子任务释放 | 每个队列的新到达过程 | 重新界定 fan-out burst 与通信/加载 | 不直接从单队列推出 DAG makespan |

最小建议是只输出条件式 `{work_unit, deployment_id, sigma, rho, R_lower, T_upper, premise_status, backlog_bound, virtual_delay_bound}`。未知字段不填保守猜测；先拒绝保证，再允许独立的预测排序。总预算还需单独核对显存、兼容性、通信、非抢占和故障域。跨卡聚合服务、串联服务曲线、随机排队与 Little 定律留待后续，不本轮强行扩大。

可证伪预测：若全部前提实际成立，监测到 B>σ+ρT 或 w>T+σ/R 即违反该模型推论，应查单位、初始状态、全窗口到达/服务以及离散化；不能删异常样本。有限 trace 未违反只提供有限观测支持，不能证明未来窗口保证。无前提证据不安装生产行为。
