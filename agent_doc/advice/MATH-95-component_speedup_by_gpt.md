# 局部加速、整体耗时与重叠边界

Stable-ID: candidate.component-speedup-scope@1
Status: task-scoped document candidate; not canonical, formal or model acceptance.

## 对象、前提和准确结论

同一固定工作量、输出语义和计时边界，基线串行且互不重叠的耗时 I>=0、R>=0，T=I+R>0（同一时间单位）。I 是拟优化部分，R 是其余部分。有限加速因子 s>=1，仅改变 I 为 I/s；R 保持不变。H>=0 是相对基线新增的开销，基线原有开销已经包含在 I 或 R，不能再次计入 H。令 p=I/T，h=H/T。

由定义直接得到 T'=R+I/s+H，故整体 speedup S=T/T'=1/(1-p+p/s+h)。这是以上模型的代数恒等式；不是测量数据，也不把现代公式冒充原论文原文。

若 p<1，则分母>=1-p，S<=1/(1-p)。p>0 时零开销、s趋于无穷才达到该上界的极限；p=0,H=0时S=1已经等号。p=1,H=0时S=s，不能套用有限的1/(1-p)。S>1 当且仅当 H<I(1-1/s)；等号时无净收益。s=1时H>=0使S<=1。所有比值无量纲。

## 证明与误用

将 R=T-I 代入 T' 并除以正数 T 即得恒等式。上界使用 p/s>=0,h>=0；净收益条件使用 T'<T 的等价变形。一般证明依赖明确的时间分解，不依赖样例。

FLOP占比不是p：不同操作的单位工作耗时可不同。GPU并发kernel跨度也不能相加当串行exclusive时间。输入输出形状相同不证明R不变（缓存、流水线、调度可改变）。若优化改变剩余工作量，应另写T'=R'+I/s+H并验证R'，不能保留旧p上界。负新增开销、有多个同时变化模块、吞吐/延迟计时口径混用均不在此模型。

## 四个公开手算问题（题干不提示定理）

1. 服务处理一次请求，先检索耗时10，再生成耗时90；检索耗时减半，没有额外开销。整体加速多少？T'=95，S=100/95=20/19；耗时减少5%，speedup约1.0526。即使检索耗时趋零，S最多趋于10/9。
2. 同一服务新方案检索耗时5，但新增转换耗时6。T'=101，S=100/101<1：组件变快而整体变慢。H=5时恰无净收益。
3. Agent同时启动两个无资源争用的独立工具，耗时10和90，从同时启动到两者均完成计时。加速短工具到5后整体仍90，S=1。此toy模型T=max(I,R)，不是I+R；实际工具共享资源或有启动/合并开销时还需新的模型。
4. 某索引方案同时减少后续计算，基线I=10,R=90，新方案I'=5,R'=45,H=0。T'=50，S=2没有违反旧上界，因为R不变的前提已失败。工作量减少是否保持质量未知，不能据此宣称可比部署收益。

这些样例用于开发和审阅，已经公开，不是未见测试；没有模型检索/拒用实测。

## 迁移与可证伪预测

GPU indexer→I，其后attention及其他串行步骤→R：只有相同模型/输出语义、硬件、dtype、输入形状、计时边界，且exclusive无重叠时间分解和R不变都有实测证据，才是严格映射。当前所有真实I/R/H以及输出质量未知。条件预测：p=0.1,s=2,h=0时S=20/19。匹配设置测得不同结果应检查分解/剩余时间/开销/计时噪声，并不能把旧模型硬套。

最小验证应先固定代表性请求与准确输出比较，记录同步边界和exclusive trace、并发依赖、基线与新方案I/R/H/T。改变k或不补满索引导致后续工作量变化时，单独比较质量与R'，拒绝旧固定R保证。端到端消费者尚未运行，保留探索候选；不修改生产行为。

Agent并行工具→两条独立分支，case3只保留同时开始、等待全部完成、无资源争用的max关系；真实多AI会议/数据库检索依赖图及资源争用未知。因此不能从短分支加速推出会议总耗时收益。
