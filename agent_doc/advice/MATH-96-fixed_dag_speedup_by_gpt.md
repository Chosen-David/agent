# 固定依赖图中缩短一个节点，整体能快多少

Stable-ID: candidate.fixed-dag-node-speedup@1
Status: task-scoped document candidate; production deferred, not canonical/formal/model acceptance.

## 数学对象、前提和准确结论

G=(V,E)为有限非空DAG。每个节点是必须完成的任务，固定耗时d_v>=0，边u→v表示v必须在u完成后开始。所有任务在同一计时起点可用，仅受这些依赖约束；无限资源，无争用、排队、额外启动/通信开销（已存在开销须显式建为节点）。固定工作量、输出语义和图，任务一旦就绪立即启动。时间用同一单位。

按拓扑顺序令c(v)=d_v+max_{u→v}c(u)，无父节点的max=0。最早完成全部任务的耗时T=max_{sink v}c(v)=max_{source→sink path P}sum_{u in P}d_u。T是理想并行模型的最优makespan，不自动等于真实宿主墙钟时间。

仅把节点v缩短a，0<=a<=d_v，其他耗时和边均不变。令A为所有经过v的源至汇路径中最大耗时；每个节点在某条此类路径上，因此A存在。令B为所有不经过v的源至汇路径最大耗时，没有此类路径时定义B=0。则T=max(A,B)，T'=max(A-a,B)。若A>=B，节省T-T'=min(a,A-B)；若A<B，节省0。任何不含v的同长最长路径都会阻止仅缩短v带来收益。全零、a=0和并列情况均包含；T=0时不定义speedup比值。

## 可复核证明及计算方法

对拓扑序归纳：源任务完成时间d_v；其他任务必须等所有父任务完成，其最早启动时间为父完成时间最大值。无限资源使每个就绪任务能立即运行，归纳中的下界同时可以实现。展开递推即得最长路径式；任何合法调度都不能早于依赖链上耗时之和。

DAG路径不会重复节点v，所以经过v的每条路径恰减少a，其他路径不变；分别取最大值得精确T'。当A>=B时，A-max(A-a,B)=min(a,A-B)，当A<B时两次最大值均为B。B的空集约定合法，因为A>=d_v>=a，A-a>=0。

可用拓扑动态规划算所有前向/后向最长路径，A=forward(v)+backward(v)-d_v。计算B时先加零耗时超级源/汇，保留原源/汇连接，删除v后只取原超级源到原超级汇的可达路径最大值；没有路径返回0。不得把删除后出现的新源或新汇接到超级节点，否则会引入原来不存在的替代路径。此方法只列为可执行验证路径，本轮未实现、未跑CPU基准。手算不是一般证明，归纳和路径划分才是一般论证。

## 公开开发案例（题干不提示知识名称）

1. 两项独立资料读取分别耗时10和8，必须都完成才能提交；无资源争用。同时启动后，把第一项缩短6，总耗时从10变8，节省2而非6。A=10,B=8，min(6,2)=2。
2. 两位必须到场的独立审阅者均耗时10，缩短一位6，仍等另一位10；节省0。此时该节点经过最长路径，但另有不含它的同长路径。
3. 工程流水线两条独立分支耗时10和8，二者完成后共同执行合并步骤3。合并缩短2，总耗时13→11，节省2。每条完整路径都包含合并节点，A=13,B=0；min(2,13)=2。共享节点不应在分支时间相加时重复计费。
4. 两项各耗时10的独立任务，共用一个只能串行工作的执行器。依赖图span=10，实际最优总耗时20；资源前提不成立，拒绝把span当真实时间。缩短一项到4时串行总耗时14，不能套case2的零收益。

四例是公开/开发手算，已经用于本稿和审阅，不是未见测试；没有同模型检索、拒用或质量测试。每例参数是假设，不是本机测量。

## 迁移、前提核对与可证伪预测

Agent工具/AI调用→任务节点，真实输入输出依赖及join→边，调用独占执行时间→d_v。在固定请求、图与输出质量下，只有资源无限或实际所有就绪任务确实能立即执行、耗时不随并发改变且额外等待已建模，才保留上述等式。真实API限流、GPU/CPU争用、动态重试/停止与队列状态未知，因此当前只建立条件映射，没有部署收益证据。预测case1的配置若满足前提，缩短6只能节省2；如果实测与预测不符，需检查图、资源等待和耗时变化，不强称模型已适用。

PP阶段/kernel流水线可按固定一次执行的事件与依赖建立图；资源序列化边可描述一份冻结调度。但优化后资源次序可能改变，不能把旧资源边预测当新最优调度；多请求吞吐和单请求延迟也不能混用。本轮未访问或修改SGLang/TwoLevel代码，未采集真实trace。

在有限P个相同执行器、固定任务耗时模型下，span只给下界；还至少需要sum d_v/P的工作下界。kernel并发可能改变d_v，两个下界也不能越过这一假设。最小实际验证：冻结图/请求/输出约束，记录每节点就绪/开始/结束时间及资源和等待原因，比较c(v)递推与真实完成；仅在差异可解释且所有输入固定时尝试单节点对照。
