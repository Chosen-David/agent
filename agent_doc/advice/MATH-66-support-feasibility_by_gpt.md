## 对象、假设和精确结论

有限非空行集合 I、列集合 J，允许边 E⊆I×J。a_i,b_j≥0，Σa_i=Σb_j=M<∞，质量连续且可拆分。要求 P_ij≥0，E外P_ij=0，行和a、列和b；暂不设边容量上限。对 A⊆I，定义 N(A)={j:某i∈A且(i,j)∈E}。

存在这样的 P 当且仅当对所有 A⊆I：

$$a(A)\le b(N(A)).$$

必要性：A行流出的全部质量只能进入N(A)，其总接收质量不超过b(N(A))。空集给出0≤0；孤立行必须a_i=0。孤立列若b_j>0，则A=I时b(N(I))<M，亦被拒绝；零边际点可以保留。

充分性：M=0时零矩阵即可。M>0构造 source→行i（容量a_i）、允许行列边（统一容量κ>M，同一质量单位）、列j→sink（容量b_j）。平凡割容量M，因此最小割不跨任何κ边。设源侧行集为A，源侧列必须包含N(A)，取恰好N(A)使割最小，容量为

$$M-a(A)+b(N(A)).$$

邻域条件使每个这样的割≥M，最大流/最小割给出流值M；全部源边、汇边同时饱和，得到要求的矩阵。这是有限实容量存在性论证，不承诺朴素Ford–Fulkerson对任意无理容量有限步终止。

同一割推导还给出最大部分可分配量ν：

$$\rho=\max_{A\subseteq I}(a(A)-b(N(A)))\ge0,\qquad \nu=M-\rho.$$

空集使ρ≥0。ρ是供给侧未分配质量，也是需求侧未满足质量；两侧合计的未匹配量为2ρ，不能混称ρ。某个A及正差额就是不可行证据。枚举所有子集不是轻量实现；应使用合适最大流实现找割证据，实际实现和费用尚未验证。

## 可行不等于每条允许边都严格正

E非空时，存在所有E边均正的P，等价于存在ε>0，使

$$a'_i=a_i-\varepsilon\deg_I(i)\ge0,\quad b'_j=b_j-\varepsilon\deg_J(j)\ge0$$

且残余边际满足上述全部邻域条件。两侧残余总质量均M−ε|E|。证明：从全正可行P取不超过所有允许边最小值的ε并减去；反向把ε加到残余计划的每条允许边即可。E空时正条件是空条件，但边际必须全零；M=0且E非空不可能全正。

不能把非空可行多面体的相对内部自动理解为每条名义允许边正：有些允许边在所有可行计划中强制为零。正活动核加有限实势的指数形式会让每条活动边正，因此这种形式不能以有限势精确表示强制零边；可以出现边界极限，本文不作收敛速率保证。

## 正例、边界与拒用反例

| 公开解析例 | 条件与结论 |
|---|---|
| 完全2×2 | a=(3/5,2/5)，b=(1/2,1/2)；P=((3/10,3/10),(1/5,1/5))，每条边正，边际正确。 |
| 连通但无解 | E={(1,1),(2,1),(2,2)}，a=(3/4,1/4)，b=(1/2,1/2)。A={1}差额1/4；A空、{2}、全体差额分别0、−3/4、0，所以ρ=1/4、ν=3/4。部分计划((1/2,0),(0,1/4))达到该量。每个点有边、图连通、分量总质量相等都不充分。 |
| 分量不平衡 | 对角支持，a=(3/4,1/4)、b=(1/2,1/2)，单点分量违反必要平衡。 |
| 可行却不能全正 | 同上三条连通边，a=b=(1/2,1/2)。唯一计划为对角(1/2,1/2)，允许边(2,1)强制为0。残余A={1}条件为1/2−ε≤1/2−2ε，任何ε>0都失败。 |
| 有边容量 | 单边a=b=1，但u_11=2/5。邻域条件通过仍无解，最大流2/5。有限容量必须检查一般割，不能用无容量邻域条件替代。 |
| 零质量 | M=0，任意支持的零计划可行；支持非空时无法全正。 |

有边上限u_ij时，一般割条件是对所有A⊆I、B⊆J：

$$M-a(A)+b(B)+\sum_{i\in A,j\notin B,(i,j)\in E}u_{ij}\ge M.$$

这解释容量反例；本轮没有实现通用容量求解器。

## 迁移：GPU任务与稀疏路由

固定时间窗，任务类别需完成工作(75,25)单位，两GPU有证据支持的处理量上界(50,50)同单位；类别1仅兼容GPU1，类别2兼容两者。邻域缺额25，最大可处理75，即使总容量100等于总需求100也无解。理论行→任务类别，列→GPU，边→真实兼容性，流→可拆分工作；守恒和禁止边关系被保留。窗口内容量上界（不是实测均值或保底吞吐）、可拆分性、无额外通信瓶颈是成立条件，不是从GPU数量推导出来的。

可证伪预测：若这些条件经真实资源/任务证据确认，该窗口不可能处理超过75单位；实际完成更多说明兼容图、容量或工作单位建模至少一项错误。允许类别1把25单位移至GPU2可消除这个特定缺额，但须先证明其兼容性及转移费用，不能直接改调度。

原子反例：3个不可拆的2单位作业、两个3单位容量GPU，全部兼容。连续分配可令每个作业各GPU1单位，总量6；原子作业每卡最多1个，至多完成2个作业。这不是整数最大流即可修好的问题，需完整作业变量与装箱约束；连续条件只是松弛的必要筛查。

稀疏token路由：只有当行列质量确为必须保持的确定边际、路由可分、mask固定，才可直接应用。通常attention只固定每行归一，列和不是预先规定：不能凭这套双边际模型判定普通稀疏attention无效。它也不判定token选择质量、attention输出误差或e2e精度；与MATH-65运输耦合修正不同。

## 无定理名的公开结构检查与验收边界

1. “每个块都能找到接收者，总容量够，为何仍分不了？”抽取连续需求、兼容邻域、容量；用单点/子集需求检查，不能只数边或看连通。
2. “固定mask迭代势越来越极端，允许边为何只能到零？”先分可行与全正支持；三边例说明强制零，不把数值故障自动归因实现bug。
3. “作业不许拆，连续质量判定能保证全部完成吗？”拒绝充分性，保留必要松弛检查，列明原子约束。
